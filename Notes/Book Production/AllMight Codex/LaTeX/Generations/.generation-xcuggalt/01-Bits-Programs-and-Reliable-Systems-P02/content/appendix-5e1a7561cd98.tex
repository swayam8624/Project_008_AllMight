\subsection{Const applies at each indirection level}\label{appendix-5e1a7561cd98-const-applies-at-each-indirection-level}

\hypertarget{appendix-5e1a7561cd98-const-applies-at-each-indirection-level}{}

For a pointer chain, qualification is attached to a particular level rather than to the whole expression. \BookInlineCode{{c}{o}{n}{s}{t}{\ }{T}{*}}{const\ T*} means the pointed-to \BookInlineCode{{T}}{T} is not writable through that path; \BookInlineCode{{T}{*}{\ }{c}{o}{n}{s}{t}}{T*\ const} means the pointer object itself cannot be reseated; \BookInlineCode{{c}{o}{n}{s}{t}{\ }{T}{*}{\ }{c}{o}{n}{s}{t}}{const\ T*\ const} combines both.

The distinction becomes safety-critical at multiple levels. Converting \BookInlineCode{{T}{*}{*}}{T**} to \BookInlineCode{{c}{o}{n}{s}{t}{\ }{T}{*}{*}}{const\ T**} is not generally safe: if it were allowed, code could store a pointer-to-const object into the outer pointer and later write through the original \BookInlineCode{{T}{*}}{T*}, violating const protection. Qualification conversions therefore follow stricter rules than the familiar \BookInlineCode{{T}{*}{\ }{-}{\textgreater{}}{\ }{c}{o}{n}{s}{t}{\ }{T}{*}}{T*\ -\textgreater{}\ const\ T*} case.

Engine APIs should avoid raw multi-level pointer mutation unless the ownership/indirection contract truly requires it. Spans, references to containers, output wrappers or typed handle arrays often express the real intent more clearly. A reconstruction exercise should explain each const position and demonstrate the classic unsafe hypothetical conversion.
