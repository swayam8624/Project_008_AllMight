\section*{Sparse and iterative solvers}
\chapter{Sparse and iterative solvers}\label{appendix-67c87a3d9e94-sparse-and-iterative-solvers}

Sparse storage avoids zeros when structure and scale justify its index overhead. Iterative methods replace a dense factorization with matrix-vector products and a convergence process. Conjugate gradient requires symmetric positive definiteness; preconditioning, residual criteria, and a maximum iteration count belong in the contract.

\textbf{Use it when:} large structured systems make dense storage or factorization impractical.

\textbf{Developed in Phase 8:} Sparse storage pays off when zeros and dimensions outweigh indexing overhead, while direct factorization can create fill that destroys sparsity. Iterative methods instead use matrix-vector products and stopping tests; conjugate gradient requires an SPD operator, and preconditioning, a maximum iteration count, and a true residual make convergence reviewable. \href{Continuous\%20Notes/Computing\%20Foundations\%20-\%20From\%20Bits\%20to\%20C++\%20and\%20Systems\%20APIs\#Sparse\%20storage\%20changes\%20the\%20cost\%20model}{storage and fill} · \href{Continuous\%20Notes/Computing\%20Foundations\%20-\%20From\%20Bits\%20to\%20C++\%20and\%20Systems\%20APIs\#Direct\%20and\%20iterative\%20solvers\%20suit\%20different\%20workloads}{direct versus iterative solving}
