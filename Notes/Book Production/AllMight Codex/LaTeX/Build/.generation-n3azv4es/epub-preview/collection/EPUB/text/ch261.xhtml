Coordinate Frames and Linear Systems

Reading map · Previous chapter · Next chapter

A geometric object stays fixed while its coordinate tuple changes with basis, camera, tangent, or clip frame. The chapter connects these transformations to matrix structure and linear solving, preserving distinctions among geometric points, coordinates, and numerical factorization.

By the end: Transform coordinates between named frames and select a stable linear solve from the structure of the system.

Recall question: How can two coordinate tuples differ while describing the same geometric vector, and how does a linear solve preserve that distinction?

Coordinates can change while the geometric object stays still

A basis matrix B = [ b 1   b 2   b 3 ] converts coefficients in that basis into the surrounding reference coordinates:

v = B [ v ] B .

The coordinate tuple [ v ] B says how much of each basis direction to combine. It is a description, not a second geometric vector wandering somewhere else in the world. For b 1 = ( 1 , 0 ) and b 2 = ( 1 , 1 ) , the coefficients ( 2 , 3 ) reconstruct ( 5 , 3 ) because 2 ( 1 , 0 ) + 3 ( 1 , 1 ) = ( 5 , 3 ) .

Now describe one vector using two full bases B and C . Both reconstructions must agree:

B [ v ] B = C [ v ] C .

Solving for the new coordinates gives

[ v ] C = C − 1 B [ v ] B .

The direction of this conversion matters. C − 1 B takes B -coordinates to C -coordinates. Multiplying it by a tuple already expressed in the wrong frame is a semantic error even when the matrix dimensions match.

For a concrete check, let B = I and

C = [ 1 − 1 1 1 ] , C − 1 = 1 2 [ 1 1 − 1 1 ] .

The fixed vector with standard coordinates ( 4 , 2 ) receives new coordinates ( 3 , − 1 ) . Reconstruction gives 3 ( 1 , 1 ) − ( − 1 , 1 ) = ( 4 , 2 ) . The vector did not rotate. Its coefficients changed because our measuring directions changed.

An active transformation moves the geometric vector while keeping the reference axes fixed. A passive transformation changes the coordinates used to describe the same vector. If axes are actively rotated by R relative to the old axes, a fixed vector’s components in those new axes are R − 1 v . For orthonormal rotations this inverse is R T . Thus active rotation by + 90 ∘ takes world + X to world + Y , whereas describing unchanged world + X in axes rotated by + 90 ∘ gives local ( 0 , − 1 ) .

The same distinction applies to whole frames, including their different origins. If F B and F C map frame-local points into one common parent/world frame, then

[ P ] C = F C − 1 F B [ P ] B

using homogeneous point representatives. The inverse is needed because we first leave one local description and then enter the other. This is why endpoint names such as world_from_object and camera_from_world are more useful than an unexplained name such as matrix1.

A camera is another frame, so viewing uses its inverse

Object space is the model’s authoring frame. A mesh vertex near its own origin does not say where that mesh instance is in the scene. Its origin may be a wheel axle, door hinge, character root, or artist-chosen pivot. The object’s model matrix M maps those local points into world space, the shared scene frame used to compare separate objects.

Two vertices both stored as ( 1 , 0 , 0 ) need not coincide: their model matrices may place them far apart. Compare M A P A with M B P B , not their unrelated local tuples. Large absolute world coordinates can also lose small differences through floating-point spacing; a shared frame solves meaning, not every precision problem. Camera-relative coordinates, origin rebasing and higher precision are design responses that require their own contracts.

Let C be the camera’s world frame. It maps camera-local points into world coordinates. Rendering asks the reverse question: “what are these world points in camera coordinates?” The view matrix is therefore V = C − 1 . A camera at world ( 10 , 0 , 0 ) with no rotation sees world point ( 13 , 2 , − 5 ) at view coordinates ( 3 , 2 , − 5 ) . Nothing in the world moved; the description became relative to the camera. If the camera rotates, its inverse orientation appears in V for the same reason.

Clip coordinates retain the divisor

With a projection matrix P , the full vertex chain is

P ~ clip = P V M P ~ object .

Clip space contains the four homogeneous components ( x c , y c , z c , w c ) . Normalized device coordinates, abbreviated NDC, are the three components ( x c / w c , y c / w c , z c / w c ) after perspective division. They are different stages. Applying a four-by-four matrix does not automatically include the divide in a CPU helper, and a helper named transformPoint must say whether it performs affine transformation or a projective transformation with a checked divide.

For view point ( 4 , 0 , − 5 , 1 ) , multiplication gives ( 4 , 0 , 35 / 9 , 5 ) , and division yields ( 0.8 , 0 , 7 / 9 ) . At view depth z = − 1 , the same matrix gives normalized depth − 1 ; at z = − 10 , it gives + 1 . Those endpoint checks tell us what depth convention the matrix actually implements.

A view-space point at z = 0 would have w c = 0 with this matrix, so it would not supply a finite NDC point. A pipeline sketch that blindly divides such a point is incomplete. A CPU projection routine must handle a zero, nonfinite, or policy-defined too-small divisor. A negative divisor or an out-of-volume point also requires appropriate visibility/clipping handling; dividing its numbers is not proof it should be displayed.

Graphics pipelines typically clip primitives using homogeneous inequalities before perspective division and rasterization. Clipping an edge can create new vertices; simply dropping every outside vertex would damage a triangle crossing the boundary. Different API and backend conventions affect depth range, viewport orientation, front-face rules and related setup. Preserve a declared convention through the CPU matrix, shader interface and backend rather than applying a remembered transpose or sign flip until one scene looks right.

Tangent space supplies a surface-local measuring frame

At a surface point, a tangent T , bitangent B and normal N can form a local TBN frame. When stored as columns in parent coordinates, F T B N = [ T   B   N ] converts tangent-frame coefficients into that parent description. A normal-map sample decoded to ( 0 , 0 , 1 ) should map to the local surface normal, because it selects the third basis column. For T = ( 1 , 0 , 0 ) , B = ( 0 , 0 , 1 ) and N = ( 0 , 1 , 0 ) ,

F T B N = [ 1 0 0 0 0 1 0 1 0 ] .

Its third column is ( 0 , 1 , 0 ) , so the expected mapping works. Notice that this basis has determinant − 1 : it is orthonormal but left-handed. Orthonormality and positive orientation are separate properties. If reconstructing the bitangent as B = h ( N × T ) , this example needs h = − 1 . A stored tangent handedness sign records precisely that relationship; it is not a disposable decorative attribute.

Interpolation, compression and deformation can disturb unit lengths and perpendicularity. Renormalizing a vector repairs its length when valid, but does not alone make three arbitrary axes perpendicular. Decide whether the surface frame needs re-orthogonalization, how the handedness sign is retained, and which geometric or shading normal the operation uses. Applying an ordinary basis expansion to a tangent-space direction and transforming a general geometric normal through an arbitrary deformation are related but distinct tasks.

A normal transforms as a measurement that must still vanish on tangents

Suppose a surface tangent u and normal n obey n T u = 0 . Under the object’s linear transform A , the tangent becomes u ′ = A u . We want a new normal satisfying n ′ T u ′ = 0 for every transformed tangent. Choose

n ′ = A − T n .

Then

n ′ T u ′ = n T A − 1 A u = n T u = 0.

That is the inverse-transpose normal transform. Translation does not enter because the tangent is a displacement and a normal measures directions. For u = ( 1 , 1 , 0 ) , n = ( 1 , − 1 , 0 ) and A = diag ( 2 , 1 , 1 ) , the transformed tangent is ( 2 , 1 , 0 ) and the correct normal is ( 1 / 2 , − 1 , 0 ) , whose dot product remains zero. Transforming the normal with A instead gives ( 2 , − 1 , 0 ) ; its dot product with the tangent is 3 , exposing the error.

After a valid transform, normalize a shading normal when the shading model requires a unit direction. Normalization cannot repair a normal produced by the wrong matrix, and an inverse cannot be obtained for a singular A . If independent transformed tangents still define a surface, their cross product may reconstruct a normal; if the surface collapses, there may be no unique normal to reconstruct. An almost singular transform also needs a conditioning policy, not merely an exact determinant-zero check. The earlier inversion chapter supplies the numerical reason.

Orientation needs a state that can be composed

The robot now knows where its local axes point. A rotation matrix records those three axis images explicitly, which is ideal when many vertices must pass through the same transform. But the robot’s controller also needs to store an orientation, add a small turn, and interpolate toward a target. These are related operations with different representation needs.

A proper rotation matrix has nine scalar entries but only three continuous degrees of freedom: its columns must be orthonormal and its determinant must be positive one. Three Euler angles use only three entries, but their coordinate chart becomes singular at certain orientations. A unit quaternion takes a useful middle route: four real numbers constrained to unit length. It represents orientation compactly and composes without choosing three sequential angle coordinates for every update.

We keep the chapter’s conventions throughout: active rotations of geometric vectors, a right-handed coordinate system, and column-vector matrix action. A quaternion is written scalar first, q = ( w , x , y , z ) . Multiplication is Hamilton multiplication. Under these choices, first applying q A , then q B , is represented by q B q A . An external library may expose components in a different order or use another convention. Convert at that boundary; do not repair an unexplained discrepancy by randomly transposing or negating values.

A quaternion is an algebra before it is an orientation

A quaternion is a number of the form

q = w + x i + y j + z k , w , x , y , z ∈ R .

The basis symbols obey i 2 = j 2 = k 2 = − 1 and the cyclic rules i j = k , j k = i , k i = j . Reversing one of those mixed products changes its sign: j i = − k , k j = − i , i k = − j . Addition and multiplication by an ordinary real scalar remain componentwise. Quaternion multiplication is the extra structure; it is associative but generally not commutative.

The four coefficients form a vector in R 4 , but ordinary four-dimensional vector addition is not rotation composition. It helps to group the imaginary coefficients as a three-vector u = ( x , y , z ) and write q = ( w , u ) . A quaternion with zero scalar part, ( 0 , v ) , is called a pure quaternion. It lets a three-dimensional vector enter the algebra without claiming that the vector gained another geometric coordinate.

To derive the product, expand ( w 1 + x 1 i + y 1 j + z 1 k ) ( w 2 + x 2 i + y 2 j + z 2 k ) . Products of matching imaginary basis units contribute − x 1 x 2 − y 1 y 2 − z 1 z 2 . Mixed imaginary products collect into the cross product because their signs are antisymmetric. The remaining mixed scalar/vector terms are ordinary scalar multiples. Thus

( w 1 , u 1 ) ( w 2 , u 2 ) = ( w 1 w 2 − u 1 ⋅ u 2 , w 1 u 2 + w 2 u 1 + u 1 × u 2 ) .

The minus dot product records i 2 = j 2 = k 2 = − 1 ; the cross product records the order-sensitive mixed products. This is a reconstruction method for the formula, not a mnemonic detached from it. For implementation, its vector coefficients are

x = w 1 x 2 + x 1 w 2 + y 1 z 2 − z 1 y 2 , y = w 1 y 2 − x 1 z 2 + y 1 w 2 + z 1 x 2 , z = w 1 z 2 + x 1 y 2 − y 1 x 2 + z 1 w 2 .

A general quaternion is not automatically an orientation. Identity rotation uses ( 1 , 0 , 0 , 0 ) , the multiplicative identity. The zero quaternion ( 0 , 0 , 0 , 0 ) is an additive zero with no inverse; accepting it as a rotation silently changes the input contract.

Four stored coefficients do not tell a caller which contract applies. A useful API distinguishes a general algebraic quaternion, a checked unit orientation, and a borrowed four-component view. The general type permits addition and arbitrary multiplication. The orientation type promises finite unit coefficients, so inverse-by-conjugate and optimized rotation become legal operations. A view promises only access to coefficients; it does not enforce a rotation invariant. A packed network or animation format additionally needs declared component order, scale, quantization and sign policy. Sixteen bytes on one ABI are a storage observation, not a serialized representation contract.

Conjugation gives the inverse and its precondition

Conjugation keeps the scalar and reverses the imaginary part: q ∗ = ( w , − u ) . Multiply once using the derived product:

q q ∗ = ( w 2 + u ⋅ u , 0 ) = ‖ q ‖ 2 .

The vector terms cancel and u × u = 0 . Therefore, for q ≠ 0 ,

q − 1 = q ∗ ‖ q ‖ 2 , ‖ q ‖ = w 2 + x 2 + y 2 + z 2 .

For example, q = ( 1 , 2 , 2 , 1 ) has squared norm 10 , so its inverse is ( 1 , − 2 , − 2 , − 1 ) / 10 . A unit quaternion has norm one, and only then is conjugation alone the inverse. Conjugation reverses product order: ( a b ) ∗ = b ∗ a ∗ . Norms multiply, so exact multiplication of two unit quaternions produces a unit quaternion.

The norm multiplication rule can itself be reconstructed. Compute ( a b ) ( a b ) ∗ = a b b ∗ a ∗ . Since b b ∗ = ‖ b ‖ 2 is real, it commutes with a and a ∗ , giving ‖ b ‖ 2 a a ∗ = ‖ a ‖ 2 ‖ b ‖ 2 . Taking nonnegative square roots yields ‖ a b ‖ = ‖ a ‖ ‖ b ‖ . This explains unit closure using the same conjugate identity that supplied the inverse; it does not require memorizing another unrelated rule.

Computing the norm naively can overflow before the final answer would be problematic. A checked normalization routine first rejects nonfinite inputs, finds m = max ( | w | , | x | , | y | , | z | ) , rejects m = 0 , forms s = q / m , and returns s / ‖ s ‖ . Its intermediate squares are bounded. This validates a finite direction in four-dimensional coefficient space; it does not prove that arbitrary source data was intended to be an orientation.

The sandwich turns half angles into a full rotation

Complex multiplication already rotates a plane: multiplying x + i y by cos ⁡ θ + i sin ⁡ θ produces the familiar sine/cosine rotation. For three dimensions, a single left multiplication generally sends a pure quaternion out of the pure subspace. The rotation action uses both sides:

( 0 , v ′ ) = q ( 0 , v ) q − 1 .

For the normal orientation representation, q is unit and q − 1 = q ∗ . For a nonzero quaternion of arbitrary magnitude the action with the true inverse is still a pure rotation: write q = m q ^ , where m = ‖ q ‖ > 0 , and the factors m and 1 / m cancel. By contrast, replacing the inverse with the conjugate for that nonunit input gives q ( 0 , v ) q ∗ = m 2 q ^ ( 0 , v ) q ^ ∗ , which scales the rotated vector by m 2 . These two operations must not be conflated.

Derive the axis-angle mapping by deriving its action

Let a be a unit rotation axis and try q = ( c , s a ) , with c 2 + s 2 = 1 . The first Hamilton product is

q ( 0 , v ) = ( − s a ⋅ v , c v + s a × v ) .

Multiplying that result by ( c , − s a ) cancels its scalar part. The vector part is

v ′ = ( c 2 − s 2 ) v + 2 c s ( a × v ) + 2 s 2 a ( a ⋅ v ) .

To check the algebra, the term involving two crosses reduces using ( a × v ) × a = v − a ( a ⋅ v ) . Now choose c = cos ⁡ ( θ / 2 ) and s = sin ⁡ ( θ / 2 ) . The double-angle identities give c 2 − s 2 = cos ⁡ θ , 2 c s = sin ⁡ θ , and 2 s 2 = 1 − cos ⁡ θ . Consequently,

q = ( cos ⁡ θ 2 , a sin ⁡ θ 2 ) , v ′ = v cos ⁡ θ + ( a × v ) sin ⁡ θ + a ( a ⋅ v ) ( 1 − cos ⁡ θ ) .

This is Rodrigues’ rotation formula. The axis-parallel component stays fixed, while the perpendicular component rotates in its plane. The half angle appears because the two-sided action combines its sine and cosine through double-angle identities. It is not a spare convention to change independently.

For a 90 ∘ turn around positive Z, let h = 2 / 2 and q Z = ( h , 0 , 0 , h ) . Acting on e x gives a first pure product ( 0 , h , h , 0 ) , then the final vector ( h 2 − h 2 , 2 h 2 , 0 ) = ( 0 , 1 , 0 ) . The original basis vector has turned toward positive Y as required by the right-hand rule.

Recover the axis while admitting when it is undefined

For a normalized orientation q = ( w , u ) , a useful angle is θ = 2 atan 2 ( ‖ u ‖ , w ) . When u ≠ 0 , its normalized direction is the axis. If the quaternion is the identity, the rotation angle is zero and every axis gives the same action; there is no unique physical axis to recover. A routine may return a documented arbitrary axis with a status describing that degeneracy.

Choosing the sign of q changes the reported axis-angle representative. For a shortest-angle report, one may choose the representative with w ≥ 0 , giving an angle in [ 0 , π ] , with an additional tie rule at w = 0 . This is a reporting convention. It can jump near the boundary and should not be imposed blindly on every frame of a continuous animation.

Remove the redundant arithmetic only after preserving the proof

Write a unit quaternion as q = ( w , u ) . Expanding the sandwich gives

v ′ = ( w 2 − u ⋅ u ) v + 2 u ( u ⋅ v ) + 2 w ( u × v ) .

Use w 2 + u ⋅ u = 1 and u × ( u × v ) = u ( u ⋅ v ) − v ( u ⋅ u ) . Then define t = 2 u × v to obtain

v ′ = v + w t + u × t .

For q Z and v = ( 1 , 0 , 0 ) , t = ( 0 , 2 , 0 ) , w t = ( 0 , 1 , 0 ) , and u × t = ( − 1 , 0 , 0 ) ; the sum is ( 0 , 1 , 0 ) . The optimized form is a useful computational result because we can explain its agreement with the literal sandwich. Off the unit sphere it is generally neither the true-inverse action nor simply the conjugate sandwich; validate or restore the input invariant instead of assuming one error model.

One adversarial input makes the three contracts visible. Double every coefficient of q Z , obtaining q = 2 q Z = ( 2 , 0 , 0 , 2 ) , and keep v = ( 1 , 0 , 0 ) . The true inverse is q − 1 = q Z ∗ / 2 , so the two scale factors cancel and the action still gives ( 0 , 1 , 0 ) . The conjugate-only sandwich instead produces ( 0 , 4 , 0 ) , because ‖ q ‖ 2 = 4 . In the unit-optimized formula, however, t = ( 0 , 2 2 , 0 ) , w t = ( 0 , 4 , 0 ) , and u × t = ( − 4 , 0 , 0 ) . Its answer is ( − 3 , 4 , 0 ) , whose length is five. It is not even the same direction as the conjugate-sandwich result.

This counterexample explains why a debug norm assertion and a checked construction boundary are worthwhile. The optimized routine has a legitimate narrow precondition; it is not defective for requiring unit inputs. The API becomes defective when it exposes unrestricted coefficients while presenting the routine as valid for every quaternion. Apply q A , then q B :

q B ( q A p q A − 1 ) q B − 1 = ( q B q A ) p ( q B q A ) − 1 .

Associativity lets the products regroup; it never permits reversing them. The rightmost turn happens first under our action. As a complete check, take q Z = ( h , 0 , 0 , h ) and q Y = ( h , 0 , h , 0 ) . Their product is

q Y q Z = ( 1 2 , 1 2 , 1 2 , 1 2 ) .

It is unit length and encodes 120 ∘ about ( 1 , 1 , 1 ) / 3 . It sends X to Y, Y to Z, and Z to X. In reverse order, q Z q Y = ( 1 / 2 , − 1 / 2 , 1 / 2 , 1 / 2 ) ; X first goes to negative Z under the Y turn and stays there under the Z turn. The product order changes the physical result.

Suppose q maps an object’s local directions into world space. A delta expressed in the object’s local axes acts before that existing map, so q new = q Δ q . A delta expressed in fixed world axes acts afterward, so q new = Δ q q . Neither multiplication side is universally correct; the delta’s frame determines it. The same rule explains why world-space angular velocity uses q ˙ = 1 2 ( 0 , ω W ) q , while local angular velocity uses q ˙ = 1 2 q ( 0 , ω L ) under these conventions.

The sign changes the stored value without changing the orientation

The inverse of − q is − q − 1 , so ( − q ) p ( − q ) − 1 = q p q − 1 . Thus q and − q are different algebraic values with the same three-dimensional rotation action. Unit quaternion coefficients lie on S 3 , the unit sphere in four-dimensional coefficient space; opposite points correspond to the same physical orientation. This is the double cover.

A 360 ∘ axis-angle turn gives ( − 1 , 0 , 0 , 0 ) and therefore identity action, while 720 ∘ returns the coefficients to ( 1 , 0 , 0 , 0 ) . A chosen continuous quaternion trajectory can record the path between those representatives, but a final orientation does not record an object’s accumulated number of turns. Keep turn count separately if the application needs it. Component equality and orientation equality therefore answer different questions. For normalized a , b , the shortest relative angle is

δ = 2 arccos ⁡ ( min ( 1 , | a ⋅ b | ) ) .

An angular tolerance on δ has a physical interpretation. Clamping here handles small numerical excess only after finite normalized inputs have been established. Near equality, an appropriately sign-aligned relative quaternion and an atan 2 extraction can be more informative than an arccos of a nearly-one dot product.

A matrix and a quaternion should agree on every basis direction

To derive quaternion-to-matrix conversion, rotate e x , e y , and e z with the expanded action. Put those results in the columns. With normalized q = ( w , x , y , z ) this yields

R ( q ) = [ 1 − 2 ( y 2 + z 2 ) 2 ( x y − w z ) 2 ( x z + w y ) 2 ( x y + w z ) 1 − 2 ( x 2 + z 2 ) 2 ( y z − w x ) 2 ( x z − w y ) 2 ( y z + w x ) 1 − 2 ( x 2 + y 2 ) ] .

For example, the first column follows from u ⋅ e x = x and u × e x = ( 0 , z , − y ) . Its result is ( 1 − 2 y 2 − 2 z 2 , 2 x y + 2 w z , 2 x z − 2 w y ) . Nothing about row-major or column-major memory storage enters this derivation; those choices only determine how the logical entries are indexed in memory.

For q Z , the matrix is exactly the familiar [ 0 − 1 0 1 0 0 0 0 1 ] in real arithmetic. For ( 1 / 2 , 1 / 2 , 1 / 2 , 1 / 2 ) , its columns are Y, Z and X. Tests should compare the matrix and quaternion actions on multiple vectors, not compare a screenshot that happens to look plausible from one camera.

Recover a large component instead of dividing by a nearly-zero one

Inverting the representation map requires choosing one of q , − q . From the matrix diagonal,

4 w 2 = 1 + r 00 + r 11 + r 22 , 4 x 2 = 1 + r 00 − r 11 − r 22 , 4 y 2 = 1 − r 00 + r 11 − r 22 , 4 z 2 = 1 − r 00 − r 11 + r 22 .

If the w expression is well conditioned, choose w > 0 from its square root and recover x = ( r 21 − r 12 ) / ( 4 w ) , y = ( r 02 − r 20 ) / ( 4 w ) , z = ( r 10 − r 01 ) / ( 4 w ) . Near a 180 ∘ turn, w approaches zero; those divisions become poor choices. Choose the largest of the four squared-component expressions instead. If x is selected, recover it first, then use

w = r 21 − r 12 4 x , y = r 01 + r 10 4 x , z = r 02 + r 20 4 x .

The Y and Z branches follow the same diagonal/symmetric-entry logic. At an exact 180 ∘ X turn, R = diag ( 1 , − 1 , − 1 ) , so the X expression is 4 and the branch safely produces ( 0 , 1 , 0 , 0 ) without dividing by w = 0 .

The input must be a finite matrix close to a proper rotation, with R T R ≈ I and det R ≈ 1 . A scale, shear or reflection is outside that conversion contract. Tiny negative radicands caused by rounding can be handled with a narrow documented numerical policy; blindly clamping arbitrary invalid matrices hides the wrong input. Extracting a nearest rotation from a general affine matrix is a separate problem, for which polar decomposition or SVD supplies principled tools later.

Animation asks for a path, not merely an intermediate tuple

An animation needs orientations between unit endpoints q 0 and q 1 . Componentwise matrix averaging can collapse an object: the midpoint between the 2D identity and a 180 ∘ rotation is the zero matrix. Raw quaternion linear interpolation stays on a chord, not the sphere:

ℓ ( t ) = ( 1 − t ) q 0 + t q 1 , 0 ≤ t ≤ 1.

From identity to a 180 ∘ Z quaternion, the midpoint is ( 1 / 2 , 0 , 0 , 1 / 2 ) with norm 1 / 2 . Normalized linear interpolation, NLERP, divides that chord point by its length. It follows the same short great-circle route after suitable sign handling, but its parameter does not advance at constant angular speed.

Before either NLERP or SLERP, choose consistent endpoint signs. If q 0 ⋅ q 1 < 0 , negate the target. This selects a nearer representative of the same target orientation. Otherwise interpolating q 0 and − q 0 would reach the zero quaternion at the midpoint despite both endpoints meaning the same orientation. At a physical relative angle of exactly 180 ∘ , the dot is zero and there are two equally short rotation paths; an application that needs stable direction must choose a tie-breaking or continuity policy.

Derive SLERP in a two-dimensional plane inside four dimensions

After sign alignment, let d = q 0 ⋅ q 1 = cos ⁡ Ω , with 0 ≤ Ω ≤ π / 2 . For distinct endpoints, define

u = q 1 − q 0 cos ⁡ Ω sin ⁡ Ω .

This u is a unit vector in quaternion coefficient space, perpendicular to q 0 . It is not a three-dimensional rotation axis. The endpoint decomposition is q 1 = q 0 cos ⁡ Ω + u sin ⁡ Ω . Advancing a fraction t along the unit circle in this plane gives q ( t ) = q 0 cos ⁡ ( t Ω ) + u sin ⁡ ( t Ω ) . Substitute u and use the sine-subtraction identity:

slerp ( q 0 , q 1 , t ) = sin ⁡ ( ( 1 − t ) Ω ) sin ⁡ Ω q 0 + sin ⁡ ( t Ω ) sin ⁡ Ω q 1 .

At the endpoints the weights reduce to ( 1 , 0 ) and ( 0 , 1 ) . The orthogonal-plane form proves its norm stays one. The physical rotation advances through angle 2 t Ω , so the ideal path has constant angular speed when t advances uniformly. Easing the parameter deliberately changes that speed.

Take identity and a 120 ∘ Z rotation: q 1 = ( 1 / 2 , 0 , 0 , 3 / 2 ) . At t = 1 / 4 , SLERP gives a 30 ∘ physical turn. NLERP normalizes ( 0.875 , 0 , 0 , 3 / 8 ) ; its angle is 2 atan 2 ( 3 / 8 , 0.875 ) ≈ 27.7958 ∘ . NLERP reaches the same endpoints with different speed. Neither numerical choice is universally preferable; the motion contract decides whether constant speed matters.

The halfway case alone is therefore a weak test: on a common short arc NLERP and SLERP agree at the midpoint by symmetry, even though their quarter points differ. Test a quarter point as well as both endpoints. Also test equivalent opposite-sign endpoints, a tiny separation, and a physical half turn. Compare orientation action and unit norm, not just raw coefficient equality. A routine may legitimately return − q 1 at t = 1 after shortest-path sign alignment because it reaches the same target orientation. If the application promises raw coefficient interpolation instead, that is a different function.

When Ω → 0 , sin ⁡ ( t Ω ) / sin ⁡ Ω → t . A normalized linear blend therefore supplies a stable small-angle fallback. A practical implementation validates and normalizes both endpoints, sign-aligns them, clamps the dot against rounding excess, takes a documented near-equality branch, and checks the final finite norm. A threshold such as 0.9995 is a numerical design choice, not a geometric law. The statements here assume interpolation over 0 ≤ t ≤ 1 ; extrapolation requires its own conditioning and behavior policy.

Norm repair and sign selection solve different problems

Floating-point composition perturbs the unit constraint. Explicit Euler integration also leaves the unit sphere even in exact arithmetic because it follows a tangent-line approximation to curved motion. A renormalization policy can normalize after each update or when the measured squared-norm error exceeds a justified threshold. Use finite/range-safe normalization; a NaN can evade an ordinary if (n2 <= 0) test, and squaring extreme finite coefficients can overflow.

Normalization restores unit length. Canonicalization chooses a sign representative, for example w ≥ 0 . It does not restore length and can introduce a discontinuity at w = 0 . For sampled animation continuity, a common approach aligns each quaternion’s sign with the previous stored sample. For a single serialized orientation, a deterministic canonical sign may be useful. Different tasks call for different choices.

Angle rates are not three components of angular velocity

The panel’s orientation is a state. Angular velocity describes its instantaneous rotation. Three numbers used to label the state do not automatically have derivatives equal to angular-velocity components. This distinction connects the earlier basis lesson to a common simulation failure.

The set S O ( 3 ) consists of real matrices satisfying R T R = I and det R = 1 : length-preserving, orientation-preserving three-dimensional rotations. It is not a vector space under ordinary matrix addition. Adding two valid rotations does not generally yield another valid rotation. A configuration is the current state, and a local coordinate chart assigns numerical parameters to a neighborhood of configurations. Euler angles provide one such local description, with singularities analogous to the loss of a longitude direction at a geographical pole.

Declare a convention before deriving anything. Here use column vectors, active right-handed rotations, and

R = R z ( ψ ) R y ( θ ) R x ( ϕ ) ,

where ψ is yaw, θ pitch and ϕ roll. The rightmost rotation acts first. Contributions to world angular velocity are rotations about the actual instantaneous axes:

ω = ϕ ˙ R z ( ψ ) R y ( θ ) e x + θ ˙ R z ( ψ ) e y + ψ ˙ e z .

Roll’s axis has already been moved by pitch and yaw; pitch’s axis has been moved by yaw. Define q = ( ϕ , θ , ψ ) and collect these axes as columns of E ( q ) . Then ω = E ( q ) q ˙ . This is a change from parameter rates to physical instantaneous rotation, not a fixed orthogonal basis transform.

At zero yaw and pitch, the axes are e x , e y , e z , so their rate coefficients do equal world angular-velocity components. At θ = π / 2 , the first column becomes − e z and the last remains e z . The columns are dependent. Equal nonzero roll and yaw rates can cancel to give zero angular velocity. The rigid body still has three rotational degrees of freedom; the chosen angle coordinates have become singular.

More generally, these columns give

‖ ω ‖ 2 = ϕ ˙ 2 + θ ˙ 2 + ψ ˙ 2 − 2 sin ⁡ θ ϕ ˙ ψ ˙ .

Simply summing the squared angle rates drops the cross term. Near the singularity, recovering angle rates from a small physical rotation can require very large cancelling coefficients, exactly like recovering coordinates in a nearly dependent slanted basis.

Rotational kinetic energy supplies another useful ruler. With symmetric physical inertia I w expressed in world coordinates,

T = 1 2 ω T I w ω = 1 2 q ˙ T E T I w E q ˙ .

The matrix E T I w E measures kinetic cost in angle-rate coordinates. It can lose rank at a chart singularity even when the physical body’s inertia is positive definite. That is a coordinate failure, not disappearance of physical inertia. Re-expressing orientation with a quaternion or rotation matrix avoids this particular chart problem, while introducing its own representation constraints and integration requirements.

Euler coordinates remain useful when their chart is explicit

Editors often expose roll, pitch and yaw because people can reason about named controls. The names do not specify an equation. Here roll ϕ is about X, pitch θ about Y, and yaw ψ about Z, with

R = R Z ( ψ ) R Y ( θ ) R X ( ϕ ) .

With active column-vector action this means fixed-axis X, then Y, then Z. Three distinct axes form a Tait–Bryan sequence, informally included under “Euler angles”; a proper Euler sequence repeats its first axis, such as ZXZ. State the actual matrix product rather than relying on an ambiguous “XYZ” label.

Writing c ϕ = cos ⁡ ϕ , s ϕ = sin ⁡ ϕ and similarly for the other angles, multiplication gives

R = [ c ψ c θ c ψ s θ s ϕ − s ψ c ϕ c ψ s θ c ϕ + s ψ s ϕ s ψ c θ s ψ s θ s ϕ + c ψ c ϕ s ψ s θ c ϕ − c ψ s ϕ − s θ c θ s ϕ c θ c ϕ ] .

At θ = π / 2 , this reduces to

R = [ 0 sin ⁡ ( ϕ − ψ ) cos ⁡ ( ϕ − ψ ) 0 cos ⁡ ( ϕ − ψ ) − sin ⁡ ( ϕ − ψ ) − 1 0 0 ] .

Only the difference ϕ − ψ remains. The triples ( 0 ∘ , 90 ∘ , 30 ∘ ) and ( 10 ∘ , 90 ∘ , 40 ∘ ) consequently give the same orientation. The Euler parameterization has lost local independence between two controls; the physical orientation and its matrix remain valid. This is the coordinate singularity called gimbal lock. Storing a quaternion avoids that Euler chart singularity, but converting back to Euler controls reintroduces it. No representation can change the mechanical constraints of real nested gimbals.

Conversion cannot recover a historical sequence that was discarded

Construct Euler-to-quaternion conversion from q = q Z ( ψ ) q Y ( θ ) q X ( ϕ ) . Let c r , s r denote cosine/sine of ϕ / 2 , c p , s p of θ / 2 , and c y , s y of ψ / 2 . Hamilton multiplication gives

q = ( c r c p c y + s r s p s y , s r c p c y − c r s p s y , c r s p c y + s r c p s y , c r c p s y − s r s p c y ) .

For ( ϕ , θ , ψ ) = ( 0 , 90 ∘ , 90 ∘ ) , this is ( 1 / 2 , − 1 / 2 , 1 / 2 , 1 / 2 ) . The X coefficient is not a stored X angle; it arises from the product. This is another useful cross-check against the misconception that quaternion components are axis rotations.

In the ordinary extraction branch, choose θ ∈ [ − π / 2 , π / 2 ] . Then

θ = arcsin ⁡ ( − r 20 ) , ϕ = atan 2 ( r 21 , r 22 ) , ψ = atan 2 ( r 10 , r 00 ) .

Rigid motion adds translation without adding scale or shear

A rigid transform acts as p ′ = R p + t , preserving lengths and relative angles. It is perfectly reasonable to store a position vector and a unit quaternion separately. A dual quaternion packages the same rigid motion into one composable algebraic object.

Introduce a commuting symbol ε with ε 2 = 0 but ε ≠ 0 . A dual quaternion is q ^ = q r + ε q d , where both q r and q d are ordinary quaternions. The subscript “real” here distinguishes the two quaternion parts; q r is not generally a scalar-only quaternion.

For unit rotation q r and translation pure quaternion T = ( 0 , t ) , use

q d = 1 2 T q r , T = 2 q d q r ∗ .

The order is part of the convention. Multiplying two dual quaternions gives

( a r + ε a d ) ( b r + ε b d ) = a r b r + ε ( a r b d + a d b r ) .

The second-order term vanishes because ε 2 = 0 . This matches rigid-transform composition when the rotation and translation encodings above are used. For pure translation ( 2 , 0 , 0 ) with identity rotation, q r = ( 1 , 0 , 0 , 0 ) and q d = ( 0 , 1 , 0 , 0 ) ; recovery doubles the vector part of q d and obtains the original translation.

For the same translation combined with the positive-Z quarter turn, q r = ( h , 0 , 0 , h ) and q d = ( 0 , h , − h , 0 ) . The dual part’s negative Y coefficient does not mean that the body translated in negative Y. It is a coefficient in the coupled encoding. Multiplication by q r ∗ recovers ( 0 , 1 , 0 , 0 ) , and the factor two recovers ( 2 , 0 , 0 ) . Treating the dual vector coefficients directly as a position would be as mistaken as treating quaternion x , y , z directly as Euler angles.

We can verify the composition rule without appealing to its name. For transforms A and B, substitute a d = 1 2 T A a r and b d = 1 2 T B b r into the dual product. Its dual part becomes 1 2 ( a r T B b r + T A a r b r ) . Multiply on the right by ( a r b r ) ∗ = b r ∗ a r ∗ and double. The result is T A + a r T B a r ∗ : translation A plus translation B rotated into A’s frame. The real part is a r b r . These are exactly the ordinary rigid composition equations, in the same order.

Two coupled constraints make the eight coefficients a rigid motion

An arbitrary pair of quaternions is not automatically a valid rigid dual quaternion. The unit rigid constraints are

‖ q r ‖ = 1 , q r ⋅ q d = 0 ,

where the dot is the ordinary four-component dot product. The second condition makes the recovered translation pure: the scalar part of q d q r ∗ is q d ⋅ q r . The translation construction satisfies this condition because T is pure.

Blending dual quaternions requires aligning signs of both halves together and restoring the coupled constraints. Normalizing q r and q d independently is incorrect and fails even for zero translation, whose q d is zero. Given finite blended ( r , d ) with a = ‖ r ‖ ≠ 0 , one projection to the constraints is r ′ = r / a , d 0 = d / a , d ′ = d 0 − r ′ ( r ′ ⋅ d 0 ) . It removes the dual component parallel to the real part. Degenerate cancellation and application-specific skinning weights still require an explicit failure policy.

Dual-quaternion blending can reduce characteristic matrix-blend twisting artifacts in suitable rigid skinning problems. It does not make an arbitrary weighted blend an exact physical interpolation, and a conventional rigid dual quaternion cannot encode general nonuniform scaling, shear or reflection. Choose it for the rigid domain it actually represents.

A transform type must say what its stored fields mean

For a local authoring transform, choose finite translation t , unit orientation q , and axis scales s = ( s x , s y , s z ) , with matrix convention M = T R S . The Hadamard product ⊙ means componentwise multiplication. A local point and direction then follow different paths:

p ′ = t + R ( q ) ( s ⊙ p ) , v ′ = R ( q ) ( s ⊙ v ) .

Translation applies to points because their location changes; a free vector has no location to translate. The transform’s linear part is A = R S . Its matrix columns are the rotated local basis directions multiplied by their respective scales, and its last homogeneous column contains translation.

For a point inverse, solve the steps backward:

p = s − 1 ⊙ R ( q ) T ( p ′ − t ) ,

requiring each scale component to be nonzero. The inverse operation is well defined under those conditions even when its result cannot be stored as another transform with the same restricted T R S field convention. Finite input does not promise a finite or usable inverse: very small scales can overflow reciprocals or amplify uncertainty severely. Return a status when the requested operation is invalid or outside the numerical contract.

Normals undo scale before following rotation

A normal is a measurement covector whose zero action identifies tangent directions. Preserving that relation requires n ′ = A − T n . For A = R S and orthogonal R ,

A − T = ( S − 1 R T ) T = R S − 1 .

Therefore apply reciprocal scale to the normal, rotate, and normalize when a unit shading direction is wanted. Never translate a normal. Zero scale makes the inverse-transpose undefined; an implementation may reconstruct a geometric normal from surviving transformed tangents when they remain independent, but that is a separate operation with its own degeneracy case.

For example, use tangent ( 1 , 1 , 0 ) and normal ( 1 , − 1 , 0 ) with S = diag ( 2 , 1 , 1 ) and identity rotation. The tangent becomes ( 2 , 1 , 0 ) while the unnormalized normal becomes ( 1 / 2 , − 1 , 0 ) ; their dot is zero. Transforming both with S instead would give dot 3 and break perpendicularity. Negative determinant additionally reverses orientation: a cross-derived area normal carries determinant sign as well as inverse-transpose direction. Keep face winding, geometric area and shading-normal policies distinct.

The world result may no longer fit the local authoring fields

Rigid transforms are closed under composition. Applying local transform B and then parent A gives R C = R A R B and t C = t A + R A t B , or q C = q A q B . This is why position plus quaternion is such a convenient rigid representation.

With nonuniform scale, the linear product becomes R A S A R B S B . The middle factors generally cannot be swapped, and the result need not equal any proper rotation times a diagonal scale. A concrete planar example makes the issue measurable. Let S = diag ( 2 , 1 ) and R be a 45 ∘ rotation. The columns of S R are ( 2 , 2 / 2 ) and ( − 2 , 2 / 2 ) . Their dot is − 2 + 1 / 2 = − 3 / 2 , so they are not perpendicular. The columns of any R ′ D ′ with orthogonal R ′ and diagonal D ′ must be perpendicular. Consequently this composed map cannot be represented exactly by that restricted rotation/diagonal-scale form.

The same structural problem affects inverse storage: ( R S ) − 1 = S − 1 R T , while storing inverse fields in the original order would yield R T S − 1 . Uniform scale commutes with rotation; arbitrary nonuniform scale does not. Some particular rotations and scale patterns also commute, but they are conditions to verify, not a default assumption.

The failure is a property of the restricted representation, rather than an inability to invert the underlying map. A general invertible affine matrix remains closed under inversion. A TRS object can consequently provide inverseTransformPoint by reversing its operations, or provide an inverse affine matrix, while correctly declining to promise another exact TRS object. Returning a transform with guessed reciprocal scales and inverse orientation silently changes the operation. The return type and name should express whether the result is exact, approximate, or potentially unavailable. Store editable local transforms as TRS when useful, and compute general world affine matrices by hierarchy multiplication:

M world , child = M world , parent M local , child .

If an editor requests world TRS, disclose whether decomposition is exact, includes shear, or returns an approximation. A quaternion cannot absorb a reflection because its rotation has determinant positive one. A zero-scale matrix can still map points forward but has no inverse. These are API facts, not exceptional nuisances to hide behind a default identity result.

A cached matrix is a dependency promise

Suppose local position, orientation and scale are canonical, while the matrix is cached for repeated use. A setter changes position but leaves the old matrix bytes in place until recomputation. The flag localDirty means exactly that those bytes no longer represent the current canonical fields. It does not mean that the transform data is corrupt.

World state has another dependency: parent world times local. If a door rotates on a car, the door’s local and world values become dirty. A mirror attached to the door keeps the same local placement relative to the door, so its local matrix remains valid; its world matrix becomes dirty. The car’s local and world matrices need not change. Cached world inverses and normal matrices become stale whenever their underlying world matrix changes.

Either strategy needs one authoritative representation. Independently writable TRS and matrix fields create conflicting truths.

Boolean propagation can mark an affected subtree. Version wrap, stale handles, concurrent readers and writes, and graph cycles still need system-level policies. A mutable lazy cache is not automatically safe to access from multiple threads.

Reparenting is a useful stress test because it changes a dependency without necessarily changing the child’s local coefficients. If a node is attached to a different parent while retaining its local TRS, its local matrix can stay valid while its world matrix must be invalidated. If the editor instead promises to preserve the world pose, it must solve for a new local affine map using the new parent’s inverse, and then determine whether that map fits the allowed local TRS representation. A robust interface reports that situation instead of disguising it as a successful unchanged pose.

A cache reference also has a lifetime and mutation contract. Returning const Mat4& avoids a copy, but later recomputation can change the referenced object. The useful result is not a winning representation. It is an explicit contract at every conversion and a test that can reveal when that contract was broken.

There is also a workload reason to keep these representations together. Composing an orientation once per object update and transforming a large vertex buffer are different tasks. The graphics problem hiding inside a matrix equation

Imagine a graphics engine fitting a flat surface to noisy depth samples, solving for a camera correction, estimating the dominant direction in a point cloud, or integrating a small deformation over time. Every one of these tasks asks a related question: what does a collection of linear measurements allow us to know, and how can we compute that answer without inventing information the data did not contain?

We will follow one chain. A row of a matrix is a measurement or constraint. A system asks for an input satisfying many such measurements. Elimination reveals which constraints are independent and which degrees of freedom remain. Factorizations organize that elimination so it can be reused and made stable. Eigenvectors identify directions preserved by a square map; singular vectors do the more general job of identifying input directions that are stretched into mutually perpendicular output directions. From that picture come least squares, pseudoinverses, PCA, low-rank approximation, polar decomposition, and a principled view of matrix functions. Constraints, rank, and what data can determine

Many graphics tasks ask for an unknown vector x that satisfies measured constraints. A collection of linear measurements has the form

A x = b ,

where each row of A describes one scalar measurement of x , and the matching entry of b is the observed value. A single equation in three unknowns usually describes a plane; several equations describe the intersection of planes. The intersection can be one point, a line or plane of solutions, or empty if the observations conflict.

Rank is the number of independent constraints, equivalently the number of independent rows or columns. If A has n columns and rank r , then its nullspace has dimension n − r . A vector z in this nullspace satisfies A z = 0 , so x and x + z produce the same measurements. This is the algebraic form of ambiguity: the data cannot distinguish those alternatives. Rank is not merely a property of a matrix algorithm. It says which degrees of freedom the experiment observes.

Consider two measurements of a three-component unknown:

[ 1 0 1 0 1 1 ] [ x 1 x 2 x 3 ] = [ 4 5 ] .

There are two independent equations and three unknowns. Let x 3 = t ; then x 1 = 4 − t and x 2 = 5 − t . Every value of t gives a solution. The free parameter is not a defect of elimination. It is a direction the measurements do not determine. A regularizer, prior, extra view, or physical constraint can choose among solutions, but that choice adds information or preference that was not present in the original equations.

When noisy observations make exact equality impossible, choose x to minimize the residual r = A x − b . Least squares minimizes ‖ A x − b ‖ 2 2 . Orthogonal transformations preserve Euclidean lengths, which is why QR factorization is valuable: writing A = Q R separates the component of b explained by the columns of A from the orthogonal residual that no parameter choice can remove. The residual measures mismatch; it does not alone tell whether the estimated parameters are trustworthy. If small changes in b cause large changes in x , the problem is ill-conditioned even when the computed residual is tiny.

Singular values make this distinction visible. For A ∈ R m × n , a singular value decomposition has the form

A = U Σ V T ,

where the columns of U and V are orthonormal directions and the diagonal entries σ i ≥ 0 of Σ are the stretch factors along paired input and output directions. A zero singular value marks a direction erased by the map. A very small singular value marks a direction that is almost erased: inversion along it amplifies noise by approximately 1 / σ i . Thus numerical rank depends on a tolerance tied to scale and uncertainty; it is not always a crisp count encoded by exact zeros.

The Moore–Penrose pseudoinverse chooses a least-squares solution, and among tied least-squares solutions chooses the one with minimum Euclidean norm. This is a mathematically precise convention, but “minimum norm” depends on the metric and parameter units. If one parameter is measured in meters and another in micrometers, an unweighted Euclidean norm silently treats their raw numbers as comparable. Rescaling or weighting changes the preferred answer. Keep the units and metric beside the optimization objective.

A linear equation is a measurement, and several equations are geometry

Start with one equation in two unknowns:

2 x + y = 5.

Each pair ( x , y ) is a point in the plane. The equation selects a line: every point on it satisfies the same measurement. In three variables one nontrivial linear equation selects a plane, and in n variables it selects a hyperplane. Here hyperplane means the flat set one dimension lower than the ambient space. The coefficients ( 2 , 1 ) set the measurement direction; the right side 5 moves the set without changing its orientation.

Several equations ask for the intersection of their constraint sets. Parallel distinct lines have no common point; distinct lines crossing once have one; repeated equations leave a whole line of answers. This geometric picture explains why the number of equations alone does not tell us how many independent facts we have. We need rank.

Write the linear system compactly as

A x = b , A ∈ R m × n , x ∈ R n , b ∈ R m .

The row view says each row of A tests the unknown vector and produces one scalar measurement. The column view says A x is a weighted sum of the columns of A . Therefore an exact solution exists precisely when b can be made from those columns:

A x = b  is consistent ⟺ b ∈ Col ( A ) .

This is a powerful diagnostic. If a measured target lies outside the reachable column space, no amount of more careful elimination will make an exact solution exist. We must instead change the model, accept an approximation, or report failure.

Use the running system

x + y + z = 6 , 2 x − y + z = 3 , x + 2 y − z = 2.

Its matrix form is A x = b with rows ( 1 , 1 , 1 ) , ( 2 , − 1 , 1 ) , ( 1 , 2 , − 1 ) and target ( 6 , 3 , 2 ) T . The solution ( 1 , 2 , 3 ) T can be checked by substituting into the original measurements. Keeping this direct check in view matters: a transformed system is only useful if it preserves the same solution set.

A system is an intersection of constraints

One nontrivial equation a 1 x 1 + ⋯ + a n x n = b describes an ( n − 1 ) -dimensional hyperplane in R n . Its normal vector is a = ( a 1 , … , a n ) T : moving parallel to the hyperplane changes the point while keeping the dot product with a fixed. The scalar b selects which parallel hyperplane is meant. For a ≠ 0 , the plane’s signed offset along its chosen unit normal is b / ‖ a ‖ 2 , and its closest point to the origin is b a / ‖ a ‖ 2 2 : that point is parallel to the normal and satisfies a T x = b . If a = 0 , the equation is exceptional: it says either 0 = b , which is always true when b = 0 , or an impossibility when b ≠ 0 .

Stacking m equations gives A x = b , with A ∈ R m × n , x ∈ R n , and b ∈ R m . Each row is a constraint on the same unknown. Geometrically, solutions are points in the intersection of those hyperplanes. The intersection can be empty, a single point, or an affine flat with positive dimension. More equations do not necessarily mean more information: a duplicate or a linear combination of earlier rows adds no independent constraint.

The fundamental-subspace view keeps the reachable outputs and invisible inputs distinct.

There is a second view that is equally useful. Writing the columns as a 1 , … , a n , the product is A x = x 1 a 1 + ⋯ + x n a n . Thus a solution exists exactly when b is in the column space of A . The row view explains the constraints; the column view explains which outputs are reachable. For an overdetermined data fit, an observed target may lie outside that reachable space, so an exact solution does not exist even though an approximate fit does.

For example,

[ 1 2 1 2 4 2 1 1 0 ] [ x y z ] = [ 4 8 1 ]

has three equations but only two independent constraints. The first two rows and right-hand sides repeat the same equation at double scale. From x + y = 1 , write x = t and y = 1 − t ; then x + 2 y + z = 4 gives z = t + 2 . Thus every solution is ( t , 1 − t , t + 2 ) T . The solution set is a line, not one point. If the second target changes from 8 to 9 , the first two equations demand both x + 2 y + z = 4 and 2 x + 4 y + 2 z = 9 , an inconsistency.

Immediate footing — gauge freedom

Gauge freedom means different parameter values describe the same observable configuration, so the parameters are not uniquely determined without a convention or anchor. Translating and rotating an entire scene and all cameras together may leave every image unchanged; absolute world pose is therefore unobservable. Fix a reference camera pose to choose world origin and orientation, and fix a baseline or known length when scale is also free. These choices select a representative solution, not an absolute truth. Gauge freedom produces singular directions in the equations, which calibration and optimization must identify and handle.

Rank separates what the measurements determine from what they leave free

The row space is the span of the measurement rows. It records the independent linear tests the system can make. The column space is the set of outputs the map can produce. The null space is the set of input changes invisible to every measurement:

Null ( A ) = { z : A z = 0 } .

If x 0 is one solution, every solution is x 0 + z for some z ∈ Null ( A ) . The null vector is not measurement error; it is a direction the system cannot observe. In graphics, this can represent a gauge freedom, an unconstrained parameter, or a motion that does not change the sampled data.

The rank r is the number of independent rows, equivalently the dimension of the row space or column space. Rank-nullity says

rank ( A ) + dim ⁡ Null ( A ) = n .

The input space splits into r observable degrees of freedom and n − r invisible ones. This immediately predicts the solution shape. For a consistent system, full column rank ( r = n ) gives a unique solution. If r < n , there are free directions and infinitely many solutions. If b lies outside the column space, there is no exact solution regardless of the number of free variables.

The row space is perpendicular to the null space: every row a i T satisfies a i T z = 0 for every null vector. Thus the unobservable motions are precisely those orthogonal to all measurement directions. The left null space, Null ( A T ) , instead describes dependencies among the rows and therefore among the measurement equations. These are distinct spaces with distinct jobs.

Do not infer rank from a determinant except in the narrow square case, and do not infer reliable rank from exact floating-point equality. In exact arithmetic rank is algebraic. In finite precision, numerical rank needs a scale and a tolerance or a singular-value threshold. A tiny singular value may mean weakly observed information rather than a truly absent dimension. This distinction returns when we build the pseudoinverse and truncate an SVD.

Rank, the four spaces, and the shape of the answer

The rank r is the dimension of the row space and, by the row-column rank theorem, also the dimension of the column space. It counts independent constraints and independent reachable output directions. It is bounded by r ≤ min ( m , n ) , not automatically equal to either dimension. The four fundamental spaces describe different sides of the map:

Space Ambient space Meaning
Row ( A ) R n input directions tested by rows
Null ( A ) R n input changes invisible to the map
Col ( A ) R m outputs the map can produce
Null ( A T ) R m dependencies among row constraints

For any z ∈ Null ( A ) , every row a i T obeys a i T z = 0 . Therefore Null ( A ) = Row ( A ) ⊥ . Likewise, a vector y ∈ R m is perpendicular to every column of A exactly when A T y = 0 , so Null ( A T ) = Col ( A ) ⊥ . If r = rank ( A ) , their dimensions are n − r and m − r , respectively. These are useful geometric facts: invisible input motions lie parallel to all constraint hyperplanes through the origin, while left-null vectors express dependencies among output coordinates or equations.

x = x p + z , z ∈ Null ( A ) .

This is the complete description, not only a way to generate examples. The solution set is a translated null space, an affine subspace whose dimension is the nullity. Rank-nullity follows from the dimension theorem for the map A : R n → R m :

rank ( A ) + nullity ( A ) = n .

The input has r independent directions that affect the output and n − r independent directions that the map erases. A consistent system with r = n has a unique solution. A consistent system with r < n has infinitely many solutions over the reals because at least one free parameter can vary continuously. If b lies outside Col ( A ) , there are no exact solutions, regardless of nullity.

Here is a constructive proof of rank-nullity, with the domain made explicit. Choose a basis v 1 , … , v k for Null ( A ) , where k = nullity ( A ) . Extend it to a basis of the full input space by adding w 1 , … , w s . The images A w 1 , … , A w s span the column space: any input is a combination of the null basis and the added vectors, and the null basis maps to zero. They are also independent. If c 1 A w 1 + ⋯ + c s A w s = 0 , then c 1 w 1 + ⋯ + c s w s belongs to the null space, so it is a combination of v 1 , … , v k . That would be a dependence among the extended input basis unless every c i = 0 . Thus s = rank ( A ) = r . The extended basis has k + s = n members, proving k + r = n . The proof also explains the result: choose null directions first, then each remaining independent input direction contributes exactly one independent output direction.

This also explains several common misdiagnoses. A square matrix can be singular; its dimensions alone do not determine rank. For square A , det ( A ) = 0 is equivalent to rank deficiency and to a nontrivial null space, but determinant is not a useful general rank measure for rectangular or badly scaled matrices. Likewise, exact algebraic rank and floating-point numerical rank differ. A tiny perturbation can turn an exactly rank-one matrix into full rank, while a tiny singular value may still represent practically unobservable information. Numerical rank requires an explicit scale-aware threshold.

Suppose measurements differ by noise near machine precision. If the second pivot produced during elimination is 10 − 14 while the first is order one, declaring rank two solely because the pivot is not bitwise zero can expose an enormous apparent coefficient in the solution. Conversely, treating every small pivot as zero can discard a meaningful variable if the entire matrix is scaled near 10 − 20 . A defensible numerical decision compares pivots or singular values against both a global scale and an application tolerance. Row scaling can help when equations have different units, but it changes the metric in least squares; scaling therefore needs a model-based interpretation rather than being a cosmetic preprocessing trick.

Matrix norms give scale to residuals and error claims

A vector norm measures vector size. A matrix norm measures matrix size, but there is more than one useful choice. The induced 1-norm is the largest absolute column sum; the induced infinity norm is the largest absolute row sum. They bound how much a matrix can enlarge vectors under corresponding vector norms. The Frobenius norm is the square root of the sum of squared entries; it behaves like treating all entries as one long vector. The spectral norm is the largest singular value and equals the maximum 2-norm stretch:

‖ A ‖ 2 = σ max ( A ) .

Frobenius and spectral norms answer different questions. The Frobenius norm accounts for energy across all singular directions; the spectral norm asks for the single most amplified direction. They satisfy ‖ A ‖ 2 ≤ ‖ A ‖ F ≤ rank ( A ) ‖ A ‖ 2 . A condition number becomes concrete in norm language: κ 2 ( A ) = ‖ A ‖ 2 ‖ A − 1 ‖ 2 for invertible square A .

This language also clarifies why “the residual is small” needs a denominator and a data scale. Absolute residuals have units and change when the entire problem is scaled. Relative residuals can compare proportionally, but zero and near-zero inputs require an explicit policy. Norm choice is part of the measurement contract, not merely notation.

Matrix norms put scale into error statements

A norm assigns a nonnegative size to a matrix, vanishes only for the zero matrix, scales as ‖ α A ‖ = | α | ‖ A ‖ , and satisfies the triangle inequality. An induced norm based on vector norm ‖ ⋅ ‖ p is

‖ A ‖ p = max x ≠ 0 ‖ A x ‖ p ‖ x ‖ p = max ‖ x ‖ p = 1 ‖ A x ‖ p .

It is the largest stretch of a unit input according to that length measure, so ‖ A x ‖ p ≤ ‖ A ‖ p ‖ x ‖ p . Induced norms are submultiplicative: ‖ A B ‖ p ≤ ‖ A ‖ p ‖ B ‖ p , because first B and then A cannot stretch by more than their individual maxima.

For the vector 1-norm, triangle inequality applied to each output entry gives

‖ A x ‖ 1 = ∑ i | ∑ j a i j x j | ≤ ∑ j | x j | ∑ i | a i j | ≤ ( max j ∑ i | a i j | ) ‖ x ‖ 1 .

The bound is attained by choosing a coordinate vector at a maximum column sum, hence ‖ A ‖ 1 = max j ∑ i | a i j | . By the analogous maximum-row argument, ‖ A ‖ ∞ = max i ∑ j | a i j | . They are cheap to compute, but answer different questions: largest column sum versus largest row sum.

The Frobenius norm treats entries as one flattened vector:

‖ A ‖ F = ∑ i j | a i j | 2 = tr ( A ∗ A ) = ∑ k σ k 2 .

For real matrices A ∗ = A T . The trace identity follows because the diagonal entries of A T A are squared column lengths. If A = U Σ V ∗ , orthogonal/unitary transformations preserve this sum of squares and Σ has singular values on its diagonal, yielding the last identity. The Frobenius inner product ⟨ A , B ⟩ F = tr ( A ∗ B ) induces this norm. It measures total energy across directions, not the largest single stretch.

The spectral or operator 2-norm is ‖ A ‖ 2 = max ‖ x ‖ 2 = 1 ‖ A x ‖ 2 . SVD writes A x = U Σ V ∗ x ; V ∗ and U preserve Euclidean length, and Σ stretches coordinates by singular values. Thus ‖ A ‖ 2 = σ max . Equivalently, maximizing ‖ A x ‖ 2 2 = x ∗ A ∗ A x over unit vectors gives the largest eigenvalue of A ∗ A , so ‖ A ‖ 2 = λ max ( A ∗ A ) .

For A = [ 1 2 3 4 ] , the induced 1-norm is max ( 4 , 6 ) = 6 and infinity norm is max ( 3 , 7 ) = 7 . The Frobenius norm is 30 ≈ 5.477 . Here A T A = [ 10 14 14 20 ] has eigenvalues 15 ± 221 , so ‖ A ‖ 2 = 15 + 221 ≈ 5.465 . For the identity I 2 , Frobenius norm is 2 , but spectral norm is 1 : the map preserves every vector length, while its entries collectively have squared energy two. For rank r , σ 1 ≤ ∑ i σ i 2 ≤ r σ 1 , giving ‖ A ‖ 2 ≤ ‖ A ‖ F ≤ r ‖ A ‖ 2 .

Norm equivalence in finite dimensions means each norm bounds another up to dimension-dependent constants, not that their numerical values are interchangeable. A residual report must name its norm and scale. Absolute and relative residuals have different meanings; the denominator needs a policy when inputs are zero or near zero. See matrix norms and numerical error for the broader error vocabulary.

Elimination turns the geometry into an auditable calculation

Three elementary row operations preserve the solutions when applied to the entire augmented matrix [ A ∣ b ] : swap two rows, multiply a row by a nonzero scalar, or add a multiple of one row to another. Geometrically, these replace constraints by equivalent combinations. They change the written system but not the intersection it describes.

In row-echelon form (REF), nonzero rows appear first, each leading entry (pivot) moves right as we go down, and entries below pivots are zero. Reduced row-echelon form (RREF) additionally makes each pivot one and clears its column above. REF is enough for rank, consistency, and back substitution. RREF is uniquely determined and makes free-variable relationships easy to read, but production solvers rarely need to spend extra work reducing all the way.

Gaussian elimination derives each multiplier from the requirement that a pivot-column entry vanish. For pivot a k k ≠ 0 , row i becomes

R i ← R i − a i k a k k R k .

If a pivot is zero, swap rows. Partial pivoting chooses the largest-magnitude candidate in the current column; this avoids dividing by a zero or unnecessarily tiny value. Complete pivoting searches the full remaining submatrix and may swap columns too, so it also permutes the unknown-variable order. It can reduce growth in some cases but costs more search and bookkeeping. Partial pivoting is common, not a universal guarantee against ill-conditioning or all element growth.

The familiar forward and back substitutions are triangular solves. For lower triangular L , solve the first row then move downward; for upper triangular U , solve from the last row upward. This costs O ( n 2 ) for one right-hand side after factorization. Explicitly constructing A − 1 is generally the wrong route: a solve uses the factorization directly, avoids extra work, and avoids turning a good problem into a less stable one.

Elimination naturally produces LU factorization. With pivoting, the convention used here is

P A = L U ,

where P records row swaps, L stores elimination multipliers below its diagonal, and U stores the resulting upper triangle. This convention matters: libraries may write an equivalent permutation on the other side. A solve becomes L y = P b , then U x = y . Doolittle’s convention places ones on L ’s diagonal; other LU conventions distribute scaling differently. Never compare factors without first comparing conventions.

For many right-hand sides sharing the same A , factor once and solve each new right-hand side with the triangular factors. This is why a factorization is more than a compact identity: it amortizes expensive work. The O ( n 3 ) factorization dominates the one-time setup; each additional solve is approximately O ( n 2 ) for a dense matrix.

Row operations preserve equations for a precise reason

The three elementary row operations are: exchange two rows; multiply a row by a nonzero scalar; add a multiple of one row to another. Each can be undone, so each is multiplication on the left by an invertible elementary matrix E . The transformed system is E A x = E b . Since E has an inverse, A x = b and E A x = E b have the same solution set. This is why every operation must be applied to the right-hand side as well as to the coefficient matrix. Acting on A alone changes the equations.

Left multiplication mixes rows. It preserves the row space because each new row is a linear combination of old rows and invertibility lets us recover the old rows. It preserves rank for the same reason. It does not preserve the original column vectors: E A applies a map to every column. A safe way to use an echelon form to select a basis for the original column space is to locate pivot-column indices in the reduced matrix and then take those same indexed columns from the original A .

REF and RREF expose pivots and free variables

In row-echelon form (REF), zero rows are at the bottom; each nonzero row’s first nonzero entry, its pivot, is to the right of the pivot in the row above; and entries below each pivot are zero. Pivots need not be one, and entries above a pivot may remain nonzero. REF is enough to read rank, check consistency, and solve by back substitution.

Reduced row-echelon form (RREF) adds two conditions: each pivot equals one, and it is the only nonzero entry in its column. RREF makes the dependence of pivot variables on free variables explicit and is unique for a given row-equivalence class. For example,

[ 1 0 2 0 | 4 0 1 − 1 0 | 3 0 0 0 0 | 0 ]

has pivots in columns one and two, and free variables x 3 , x 4 . Its equations are x 1 + 2 x 3 = 4 and x 2 − x 3 = 3 , so with x 3 = s , x 4 = t the family is ( 4 − 2 s , 3 + s , s , t ) T . A bottom row [ 0   0   0   0   |   1 ] would instead be a contradiction. An all-zero coefficient row is harmless only when its right-hand side is also zero.

RREF is valuable for teaching and exact symbolic work, but it is not the default for large floating-point solves. Clearing above pivots takes extra operations and can increase roundoff exposure. A numerical solver usually stops at a triangular factor and uses substitution. RREF is an explanatory normal form, not a performance objective.

For a direct REF/RREF comparison, start from

[ 2 1 | 5 4 3 | 11 ] .

One elimination step R 2 ← R 2 − 2 R 1 gives the REF matrix [ 2 1 | 5 0 1 | 1 ] . Back substitution gives y = 1 , x = 2 . To obtain RREF, clear the entry above the second pivot with R 1 ← R 1 − R 2 , then normalize the first row by two: [ 1 0 | 2 0 1 | 1 ] . The extra work exposes the answer immediately, but it contributes no new mathematical information about the solution set. On an m × n system, an elimination path is preferable when the goal is a solve rather than a symbolic description of all variables.

Elimination multipliers become stored factor data

For a pivot a k k ≠ 0 , the entry in row i below it is removed using

m i k = a i k a k k , R i ← R i − m i k R k .

The multiplier is chosen because the new pivot-column entry is a i k − m i k a k k = 0 . In matrix form the operation is left multiplication by a lower-triangular elimination matrix with − m i k in the relevant position. Its inverse has + m i k there. Chaining these operations turns A into upper triangular U ; collecting their inverses yields a unit lower-triangular matrix L containing the multipliers, so in the no-swap case A = L U .

This is the derivation behind Gaussian elimination and pivoting.

For a concrete trace, use

A = [ 2 1 1 4 − 6 0 − 2 7 2 ] , b = [ 5 − 2 9 ] .

The first-column multipliers are m 21 = 2 and m 31 = − 1 . Subtract twice row one from row two, and add row one to row three. The result below the first pivot is [ 0 , − 8 , − 2 ] and [ 0 , 8 , 3 ] , with right-hand values − 12 and 14 . The second multiplier is m 32 = 8 / ( − 8 ) = − 1 , so row three becomes row three plus row two, giving [ 0 , 0 , 1 ] and right-hand value 2 . Back substitution gives z = 2 , − 8 y − 2 z = − 12 hence y = 1 , and 2 x + y + z = 5 hence x = 1 . The stored factors are

L = [ 1 0 0 2 1 0 − 1 − 1 1 ] , U = [ 2 1 1 0 − 8 − 2 0 0 1 ] .

Multiplication verifies L U = A . The original equations also verify ( 1 , 1 , 2 ) T . Those checks catch sign mistakes in multipliers and confusion over which matrix stores them.

Pivoting separates algorithm failure from matrix failure

An unpivoted algorithm can fail on an invertible matrix. If

A = [ 0 2 1 3 ] ,

the first pivot is zero, so the multiplier formula divides by zero; yet the determinant is − 2 and a row swap immediately permits elimination. That is algorithm failure, not singularity. Even a nonzero pivot may be too small: a pivot of 10 − 20 with an entry of size one creates a multiplier of 10 20 . Large multipliers can magnify rounding errors in subsequent subtraction.

Partial pivoting selects, at step k , the row p maximizing | a i k | over active rows i ≥ k , then swaps rows k and p . It uses the best candidate in the current column. The absolute value matters because sign does not measure size. The search costs O ( n 2 ) comparisons over a dense factorization, small beside the O ( n 3 ) elimination.

Pivoting improves algorithmic stability; it does not fix a poorly conditioned problem. Conditioning describes how sensitive the exact answer is to small changes in data. Stability describes how much extra error the algorithm introduces. A stable solver cannot rescue information the input does not contain reliably. Partial pivoting is an excellent common trade-off, not a theorem that all growth is bounded by a small constant. The element-growth factor is ρ = max i , j , k | a i j ( k ) | / max i , j | a i j | , where A ( k ) denotes the active matrix after elimination step k ; equivalently, track the largest entry generated anywhere in the elimination process (including U ) relative to the largest original entry. It is not merely the largest entry of U if intermediate states are the quantity being measured. Certain matrices exhibit large growth even under partial pivoting.

The exact algebra says row operations preserve the solution set; floating-point arithmetic adds a second question, namely how faithfully the rounded operations represent those exact operations. This is why an algebraically legitimate elimination order can still be numerically poor. Pivoting controls one avoidable source of amplification, while condition estimates and residual checks describe the remaining limitations. These are complementary diagnostics, not competing definitions of correctness.

Complete pivoting searches the whole active submatrix and swaps both a row and a column. With row and column permutation matrices P , Q , the convention is P A Q = L U . A row permutation reorders equations; a column permutation reorders unknowns. To solve A x = b , set z = Q T x . Then L U z = P b , so solve for z and recover x = Q z . Losing the column permutation can yield plausible values assigned to the wrong variables. Full searches add O ( n 3 ) comparisons and additional bookkeeping; complete pivoting is less common than partial pivoting. Rook pivoting is one practical compromise between search strength and cost.

For example, suppose the active block is [ 0 0 5 0 2 1 3 1 0 ] . Partial pivoting in the first column selects the entry 3 from the last row. Complete pivoting selects the magnitude- 5 entry in column three, so it moves both that row and that column to the first pivot position. The resulting numerical factors describe a reordered variable vector. This extra freedom can reduce pivot growth, but the bookkeeping is not decorative: after a solve, the variable permutation must be undone. A correct complete-pivot implementation should test the original equation after unpermuting x , not just inspect its internally permuted triangular solve.

Triangular solves perform the cheap second half

For lower-triangular L , row i gives L i i y i + ∑ j < i L i j y j = b i . Therefore forward substitution is

y i = b i − ∑ j = 0 i − 1 L i j y j L i i , i = 0 , 1 , … , n − 1.

If L is unit lower triangular, division disappears. For the example factor and b = ( 5 , − 2 , 9 ) T , the equations give y 1 = 5 , then 2 y 1 + y 2 = − 2 so y 2 = − 12 , then − y 1 − y 2 + y 3 = 9 so y 3 = 2 . Each new row depends on prior values, which creates a sequential dependency, though the dot-product update within one row can be vectorized.

For upper-triangular U , solve in reverse:

x i = y i − ∑ j = i + 1 n − 1 U i j x j U i i , i = n − 1 , … , 0.

The example gives z = 2 , then − 8 y − 2 z = − 12 gives y = 1 , then 2 x + y + z = 5 gives x = 1 . Each triangular solve costs about n 2 / 2 multiply-adds, or O ( n 2 ) , compared with cubic factorization. This makes reusing a factorization worthwhile when several right-hand sides share the same matrix.

Compact kernels can make the dependency and failure condition explicit:

forward(L, b):
  for i = 0 .. n-1:
    t = b[i] - dot(L[i, 0:i], y[0:i])
    if diagonal is unit: y[i] = t
    else require L[i,i] != 0; y[i] = t / L[i,i]
  return y

back(U, y):
  for i = n-1 .. 0:
    t = y[i] - dot(U[i, i+1:n], x[i+1:n])
    require U[i,i] != 0; x[i] = t / U[i,i]
  return x

The exact-zero check is illustrative for exact arithmetic. A floating-point library should use its scale, status, and singularity policy rather than treating an arbitrary universal epsilon as correct. Do not form A − 1 merely to compute A − 1 b : factor and solve. An explicit inverse generally does more work, stores more data, and introduces avoidable error.

LU and Doolittle make elimination reusable

LU packages Gaussian elimination into A = L U , where L is unit lower triangular and U is upper triangular. For A x = b , first solve L y = b , then U x = y . If rows were swapped, the correct relation is P A = L U and the first solve is L y = P b . Factorization is roughly 2 n 3 / 3 floating-point operations for dense matrices, while each subsequent triangular solve is O ( n 2 ) . This matters in graphics workloads where geometry, stiffness, or camera matrices are reused with new force or observation vectors.

See LU factorization and reusable solves for the library-facing view of the same contract.

Doolittle’s convention fixes L i i = 1 . The factor entries follow by equating the ( i , j ) entry in A = L U :

a i j = ∑ k = 0 min ( i , j ) l i k u k j .

For a given pivot column j , compute the upper row entries

u j i = a j i − ∑ k = 0 j − 1 l j k u k i , i ≥ j ,

then the lower-column entries

l i j = a i j − ∑ k = 0 j − 1 l i k u k j u j j , i > j .

The recurrence follows directly from the product, not from a memorized recipe. At j = 0 , u 00 = a 00 and each l i 0 = a i 0 / u 00 ; later columns subtract contributions already explained by earlier outer products. A zero or unsafe u j j requires pivoting or a failure report. Doolittle is one scaling convention; Crout instead normalizes the diagonal of U . A factor’s entries cannot be compared correctly until its convention is known.

An in-place LU implementation commonly stores U on and above the diagonal and the strict lower part of L beneath it. The diagonal ones of L are implicit. This saves an extra matrix but makes the storage contract important: callers must know that the returned array is packed factors, not the original matrix or a full L .

LUP carries the row permutation through the solve

With partial pivoting, row exchanges are recorded in a permutation matrix P . Under the convention P A = L U , solve

L y = P b , U x = y .

For example, take A = [ 0 2 1 3 ] and b = ( 4 , 7 ) T . Swap rows, so P = [ 0 1 1 0 ] and P A = [ 1 3 0 2 ] . Here L = I and U = P A . Then P b = ( 7 , 4 ) T , and back substitution gives y = 2 , x = 1 . Check the original order: A ( 1 , 2 ) T = ( 4 , 7 ) T . The permutation acts on the right-hand side because it acted on the equations.

For a larger matrix, a robust trace records the pivot row selected at every step, the row swaps, the multipliers, and the final factor arrays. The permutation matrix can be materialized, but production code usually stores a pivot vector. Be explicit about convention: some texts write A = P L U with P representing inverse swaps. Both can be valid if applied consistently; silently switching notation is a common source of wrong solves.

With multiple swaps, the permutation vector is updated as a sequence, not reconstructed from only the last pivot. For instance, swapping rows zero and two, then rows one and three, yields the final row order [ 2 , 3 , 0 , 1 ] relative to the original. Applying those same swaps in the same order to b produces P b . The inverse permutation would undo them in reverse order. This is why a pivot vector’s meaning must be documented: it may encode the final row order, or it may store the stepwise swap targets. Both representations are used, and their application code differs.

When swapping rows during in-place factorization at step k , swap the active row data in U and the permutation bookkeeping. Also swap the already-computed entries L k , 0 : k with those in the pivot row: those multipliers belong to the rows whose identities just exchanged. Failure to exchange these previous L columns can produce factors that do not multiply back to the permuted input even though the current U looks triangular. This detail is easy to miss because a swap happens after earlier elimination has written meaningful data below the diagonal.

An auditable factorization kernel therefore has an invariant: after each completed step, the processed columns satisfy the recorded elimination history, the remaining active submatrix is the one to be factored next, and the permutation vector describes the same row order applied to the original matrix. At the end, validate P A ≈ L U and then validate the solve residual A x − b . These are separate checks: correct factor reconstruction does not prove that the caller permuted b correctly.

Repeated right-hand sides make the value of this contract easy to quantify. If ten vectors b ( 1 ) , … , b ( 10 ) share the same A , independently eliminating ten augmented systems repeats cubic work. Factoring once and performing ten forward/back substitutions spends the cubic work once and adds roughly ten quadratic solves. The factors also expose singular pivots once, rather than allowing separate calls to make inconsistent rank decisions. If A changes each frame, that reuse disappears; the correct choice then depends on matrix size, update structure, and whether a cheaper incremental factorization exists.

A runnable pivoted LU reference preserves the elimination history

It factors a finite, nonempty square matrix with partial pivoting, stores L multipliers and U together, and follows the convention P A = L U . The pivot vector records the original row now occupying each factored row, so solving applies P b as b[pivot[i]]. The tolerance is a documented teaching rejection policy relative to the largest input entry; it is not a numerical-rank or condition estimator.

#include <algorithm>
#include <cassert>
#include <cmath>

#include <iostream>

class LUMatrix {
public:
    LUMatrix() = default; // Empty shape is representable; factorization rejects it.
    LUMatrix(std::size_t rows, std::size_t cols) : rows_(rows), cols_(cols) {
        if (rows != 0 && cols > std::numeric_limits<std::size_t>::max() / rows)
            throw std::length_error("matrix element count overflows size_t");
        const std::size_t count = rows * cols;
        if (count > data_.max_size()) throw std::length_error("matrix is too large");
        data_.assign(count, 0.0);
    }
    std::size_t rows() const noexcept { return rows_; } std::size_t cols() const noexcept { return cols_; }
    double& operator()(std::size_t r, std::size_t c) { if (r >= rows_ || c >= cols_) throw std::out_of_range("matrix index"); return data_[r * cols_ + c]; }
    double operator()(std::size_t r, std::size_t c) const { if (r >= rows_ || c >= cols_) throw std::out_of_range("matrix index"); return data_[r * cols_ + c]; }
private:
    std::size_t rows_ = 0, cols_ = 0;
    std::vector<double> data_;
};
enum class Status { NotRun, Success, InvalidDimensions, InvalidTolerance, NonFiniteInput,
                    NonFiniteIntermediate, SingularOrUnsafePivot };
std::string_view name(Status s) {
    switch (s) {
    case Status::NotRun: return "NotRun"; case Status::Success: return "Success";
    case Status::InvalidDimensions: return "InvalidDimensions";
    case Status::InvalidTolerance: return "InvalidTolerance"; case Status::NonFiniteInput: return "NonFiniteInput";
    case Status::NonFiniteIntermediate: return "NonFiniteIntermediate";
    case Status::SingularOrUnsafePivot: return "SingularOrUnsafePivot";
    }
    return "Unknown";
}
struct LUResult { LUMatrix packed; std::vector<std::size_t> pivot; Status status = Status::NotRun; };
struct SolveResult { std::vector<double> x; Status status = Status::NotRun; };
LUResult factorLU(const LUMatrix& input, double relativePivotTolerance = 1e-12) {
    LUResult out;
    if (input.rows() == 0 || input.rows() != input.cols()) { out.status = Status::InvalidDimensions; return out; }
    if (!std::isfinite(relativePivotTolerance) || relativePivotTolerance < 0.0) { out.status = Status::InvalidTolerance; return out; }
    const std::size_t n = input.rows();
    double scale = 0.0;
    for (std::size_t i = 0; i < n; ++i) for (std::size_t j = 0; j < n; ++j) {
        const double a = input(i, j);
        if (!std::isfinite(a)) { out.status = Status::NonFiniteInput; return out; }
        scale = std::max(scale, std::abs(a));
    }
    const double threshold = relativePivotTolerance * scale;
    if (!std::isfinite(threshold)) { out.status = Status::NonFiniteIntermediate; return out; }
    out.packed = input; out.pivot.resize(n);
    for (std::size_t i = 0; i < n; ++i) out.pivot[i] = i;
    for (std::size_t k = 0; k < n; ++k) {
        std::size_t p = k;
        for (std::size_t i = k + 1; i < n; ++i)
            if (std::abs(out.packed(i, k)) > std::abs(out.packed(p, k))) p = i;
        if (!std::isfinite(out.packed(p, k))) { out.status = Status::NonFiniteIntermediate; return out; }
        if (std::abs(out.packed(p, k)) <= threshold) { out.status = Status::SingularOrUnsafePivot; return out; }
        if (p != k) {
            for (std::size_t j = 0; j < n; ++j) std::swap(out.packed(k, j), out.packed(p, j));
            std::swap(out.pivot[k], out.pivot[p]); // Whole row includes prior L columns.
        }
        for (std::size_t i = k + 1; i < n; ++i) {
            out.packed(i, k) /= out.packed(k, k);
            if (!std::isfinite(out.packed(i, k))) { out.status = Status::NonFiniteIntermediate; return out; }
            for (std::size_t j = k + 1; j < n; ++j) {
                out.packed(i, j) -= out.packed(i, k) * out.packed(k, j);
                if (!std::isfinite(out.packed(i, j))) { out.status = Status::NonFiniteIntermediate; return out; }
            }
        }
    }
    out.status = Status::Success;
    return out;
}
SolveResult solveLU(const LUResult& lu, const std::vector<double>& b) {
    SolveResult out;
    if (lu.status != Status::Success) { out.status = lu.status; return out; }
    const std::size_t n = lu.packed.rows();
    if (lu.packed.cols() != n || b.size() != n || lu.pivot.size() != n) { out.status = Status::InvalidDimensions; return out; }
    for (double v : b) if (!std::isfinite(v)) { out.status = Status::NonFiniteInput; return out; }
    std::vector<double> y(n), x(n);
    for (std::size_t i = 0; i < n; ++i) {
        double t = b[lu.pivot[i]];
        for (std::size_t j = 0; j < i; ++j) t -= lu.packed(i, j) * y[j];
        if (!std::isfinite(t)) { out.status = Status::NonFiniteIntermediate; return out; }
        y[i] = t; // L has an implicit unit diagonal.
    }
    for (std::size_t ri = 0; ri < n; ++ri) {
        const std::size_t i = n - 1 - ri;
        double t = y[i];
        for (std::size_t j = i + 1; j < n; ++j) t -= lu.packed(i, j) * x[j];
        const double d = lu.packed(i, i);
        if (!std::isfinite(t) || !std::isfinite(d)) { out.status = Status::NonFiniteIntermediate; return out; }
        if (d == 0.0) { out.status = Status::SingularOrUnsafePivot; return out; }
        x[i] = t / d;
        if (!std::isfinite(x[i])) { out.status = Status::NonFiniteIntermediate; return out; }
    }
    out.x = std::move(x); out.status = Status::Success; return out;
}
bool close(double a, double b, double tol = 1e-10) { return std::abs(a - b) <= tol; }
bool reconstructs(const LUMatrix& a, const LUResult& lu) {
    const std::size_t n = a.rows();
    for (std::size_t i = 0; i < n; ++i) for (std::size_t j = 0; j < n; ++j) {
        double product = 0.0;
        for (std::size_t k = 0; k < n; ++k) {
            product += (i == k ? 1.0 : (i > k ? lu.packed(i,k) : 0.0))
                     * (k <= j ? lu.packed(k,j) : 0.0);
        }
        if (!close(product, a(lu.pivot[i], j))) return false; // P A = L U.
    }
    return true;
}

What the packed factors mean

The factor routine copies the input, so this example is out of place. Rows are swapped across the entire packed row, including columns before the active pivot. Those earlier entries already contain the multipliers of L . In the numeric example, first-column elimination writes 1 / 2 and 1 / 4 below the diagonal. At the next pivot, row 1 and row 2 exchange; these stored multipliers must exchange too. The implementation gets this right by swapping every column, not only the active suffix. Ignoring the old L region can produce a triangular-looking buffer that no longer satisfies P A = L U .

For a packed entry, read L i i = 1 , L i j = 0 above the diagonal, L i j = packed i j below it, and U i j = packed i j on or above it. The pivot vector represents the current row order: factored row i came from input row pivot[i]. Therefore reconstruction checks ( P A ) i j = A p i v o t [ i ] , j against ( L U ) i j .

The known system has x = ( 1 , 2 , 3 ) T . At the first elimination step, multipliers are 1 / 2 and 1 / 4 ; the active second-column candidates become 1 / 2 and 11 / 4 , so partial pivoting exchanges rows 1 and 2. At the last row, the earlier L values become 1 / 4 and 1 / 2 in that exchanged order. Forward substitution solves L y = P b , then reverse substitution solves U x = y . A second vector uses the same factors, demonstrating why factorization state should be separated from per-right-hand-side state.

Statuses and numerical limits

The matrix constructor checks the product of dimensions before allocation and also respects vector::max_size; allocation failure can still throw std::bad_alloc. A default empty matrix is representable to make the factor routine’s invalid-dimension status observable. Rectangular matrices are also rejected by factorization. Result objects default to NotRun; factorization and solve set Success only on their successful completion. The API reports nonfinite input, invalid tolerance, singular-or-rejected pivot, and nonfinite intermediate separately enough for a teaching trace. It checks division results and trailing updates because finite inputs can still overflow during arithmetic.

The relative pivot rule compares the selected pivot magnitude with τ max i j | a i j | . Here the default τ = 10 − 12 deliberately rejects a pivot that is tiny relative to the largest input entry. This is a conservative example policy, not an estimator of algebraic rank or condition number: row scaling, matrix structure, and the intended accuracy all affect whether such a pivot is useful. Production solvers use algorithm-specific thresholds, scaling, error estimates, and richer statuses. A rejected pivot says this teaching routine declined the factorization under its policy; it does not prove the exact matrix is singular.

The solver applies the recorded row order to b , performs unit-lower forward substitution and upper back substitution, and checks nonfinite intermediates and exact zero diagonal before division. Its precondition is an unchanged LUResult returned by a successful call to factorLU; this teaching struct is public and does not defend against callers forging or mutating packed factors or pivot data. The exact-zero check is a final structural guard; an ill-conditioned but finite solve can still return a large inaccurate answer. A separate residual and condition analysis is needed for that judgment. This lab demonstrates control flow and convention, not universal numerical reliability.

The tests assert P A ≈ L U , the stated known solution, a second right-hand side with the same factors, successful recovery from an invertible zero-leading-pivot matrix, and rejection of singular, nonfinite, and empty inputs. Assertions in this executable are checks on this small reference example. They are not a broad solver test suite, a performance benchmark, or evidence about GPU behavior. The LUMatrix is row-major and uses bounds-checked at; that favors a clear teaching example over the highest performance. The code is intentionally self-contained and uses only the C++ standard library.
