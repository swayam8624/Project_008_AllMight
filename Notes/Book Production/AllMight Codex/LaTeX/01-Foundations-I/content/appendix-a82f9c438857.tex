\textbf{Curriculum depth:} Developed · \textbf{First seen:} C007 · \textbf{Latest development:} C010

\subsection{Definition and mechanism}\label{definition-and-mechanism}

Initialization creates an occupant whereas assignment replaces an existing occupant's state. Ordinary constructor failure and post-target delegation failure have different complete-object cleanup behavior.

Storage needs sufficient size/alignment before object initialization can complete and start an ordinary lifetime. construct\_at and destroy\_at separate object life from backing storage. A cast alone does not construct arbitrary types. Some specified operations implicitly create implicit-lifetime objects; replacement and launder have additional preconditions.

M010 adds the resource-management view: placement construction or \texttt{construct\_at} uses already-provided storage; it does not allocate that storage. \texttt{destroy\_at} ends the occupant's lifetime, while an arena separately decides when to reuse or release its bytes. Explicit destruction is safe only inside a protocol that prevents accidental second destruction. See \hyperref[appendix-f56c3e43fd4e]{Placement construction and explicit lifetime management}.
