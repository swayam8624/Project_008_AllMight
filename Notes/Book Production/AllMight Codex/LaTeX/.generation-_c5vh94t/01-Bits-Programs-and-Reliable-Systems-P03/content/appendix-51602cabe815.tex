\section{Exclusive and shared smart-pointer ownership}\label{appendix-51602cabe815-exclusive-and-shared-smart-pointer-ownership}

\hypertarget{appendix-51602cabe815-exclusive-and-shared-smart-pointer-ownership}{}

\textbf{Curriculum depth:} Introduced · \textbf{First seen:} C010 · \textbf{Latest development:} C010

\begin{allmightroledefinition}

\subsection{Definition and mechanism}\label{appendix-51602cabe815-definition-and-mechanism}

\hypertarget{appendix-51602cabe815-definition-and-mechanism}{}

\texttt{std::unique\_ptr\textless{}T,\ D\textgreater{}} is a move-only exclusive owner whose deleter \texttt{D} defines disposal. \texttt{get()} exposes a borrow; \texttt{release()} transfers the responsibility without deleting. \texttt{std::shared\_ptr\textless{}T\textgreater{}} joins a shared ownership group represented by a control block; the managed object is destroyed when the last strong owner is released. The control block can outlive the object while weak observers remain. The stored pointer and the object whose destruction the control block arranges can differ (for example, aliasing ownership).

\end{allmightroledefinition}

Shared ownership is not pointee synchronization. Concurrent operations on distinct smart-pointer handles do not automatically make concurrent access to \texttt{T} safe. Use sharing only when several independent parties truly retain the same lifetime.
