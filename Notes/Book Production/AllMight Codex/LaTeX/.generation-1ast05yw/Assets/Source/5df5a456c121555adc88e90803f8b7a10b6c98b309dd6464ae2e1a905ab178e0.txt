# PART 548 — SCALAR TRIPLE PRODUCT

## 548.1 We now have two binary products

Given vectors in \(\mathbb R^3\):

\[
a,b,c.
\]

We have already learned:

\[
b\times c
\]

which takes two vectors and returns a vector.

And:

\[
a\cdot x
\]

which takes two vectors and returns a scalar.

Therefore we can compose them:

\[
\boxed{
a\cdot(b\times c)
}
\]

This quantity is called the **scalar triple product**.

It takes:

\[
\boxed{
\mathbb R^3\times\mathbb R^3\times\mathbb R^3
\rightarrow
\mathbb R.
}
\]

Three vectors in.

One scalar out.

---

# 548.2 Why this particular composition?

We already know:

\[
b\times c
\]

is perpendicular to the plane spanned by \(b\) and \(c\).

Its magnitude is:

\[
\|b\times c\|
\]

which equals the parallelogram area generated by \(b,c\).

Now dot that normal-area vector against \(a\):

\[
a\cdot(b\times c).
\]

The dot asks:

> How much of \(a\) lies along the orientation perpendicular to the \(bc\)-plane?

So immediately we should expect the scalar triple product to combine:

\[
\boxed{
\text{base area}
\times
\text{signed perpendicular height}.
}
\]

That is exactly what Part 549 will formalize as signed volume.

---

# 548.3 Coordinate derivation

Let

\[
a=(a_x,a_y,a_z),
\]

\[
b=(b_x,b_y,b_z),
\]

\[
c=(c_x,c_y,c_z).
\]

First:

\[
b\times c
=
\begin{pmatrix}
b_yc_z-b_zc_y\\
b_zc_x-b_xc_z\\
b_xc_y-b_yc_x
\end{pmatrix}.
\]

Now dot with \(a\):

\[
a\cdot(b\times c)
\]

becomes:

\[
a_x(b_yc_z-b_zc_y)
+
a_y(b_zc_x-b_xc_z)
+
a_z(b_xc_y-b_yc_x).
\]

Therefore:

\[
\boxed{
a\cdot(b\times c)
=
a_xb_yc_z
-a_xb_zc_y
+a_yb_zc_x
-a_yb_xc_z
+a_zb_xc_y
-a_zb_yc_x.
}
\]

The expression contains six products of three scalar components.

---

# 548.4 Connection to a \(3\times3\) determinant

The exact same expansion appears in:

\[
\boxed{
\det
\begin{bmatrix}
a_x&a_y&a_z\\
b_x&b_y&b_z\\
c_x&c_y&c_z
\end{bmatrix}.
}
\]

Thus:

\[
\boxed{
a\cdot(b\times c)
=
\det[a;b;c]
}
\]

where the notation means that \(a,b,c\) are arranged consistently as rows here.

If you instead use them as columns, the determinant has the same scalar value because transposing a matrix does not change its determinant—but full determinant theory comes later.

What matters now:

\[
\boxed{
\text{scalar triple product is the oriented }3\times3\text{ determinant of the three vectors.}
}
\]

---

# 548.5 Worked example

Take:

\[
a=(1,2,3),
\]

\[
b=(2,0,1),
\]

\[
c=(0,1,2).
\]

First compute:

\[
b\times c.
\]

X:

\[
0(2)-1(1)=-1.
\]

Y:

\[
1(0)-2(2)=-4.
\]

Z:

\[
2(1)-0(0)=2.
\]

So:

\[
b\times c=(-1,-4,2).
\]

Now dot with \(a\):

\[
(1,2,3)\cdot(-1,-4,2)
\]

\[
=-1-8+6
\]

\[
=\boxed{-3}.
\]

Thus:

\[
\boxed{
a\cdot(b\times c)=-3.
}
\]

Do not yet read `-3` merely as "some scalar."

Its magnitude and sign both encode geometry.

---

# 548.6 Cyclic permutations preserve the value

An important identity is:

\[
\boxed{
a\cdot(b\times c)
=
b\cdot(c\times a)
=
c\cdot(a\times b).
}
\]

These are **cyclic permutations**:

```text
a → b → c → a
```

Why?

Geometrically they describe the same oriented three-dimensional parallelepiped, merely choosing a different pair as the base.

Algebraically we can verify with the six-term expansion.

For example:

\[
b\cdot(c\times a)
\]

produces:

\[
b_x(c_ya_z-c_za_y)
+
b_y(c_za_x-c_xa_z)
+
b_z(c_xa_y-c_ya_x).
\]

Reordering scalar factors gives exactly the same six terms as before.

Thus cyclic movement does not flip the sign.

---

# 548.7 Swapping any two vectors flips the sign

Now compare:

\[
a\cdot(b\times c)
\]

with:

\[
a\cdot(c\times b).
\]

Cross anti-commutativity gives:

\[
c\times b=-(b\times c).
\]

Therefore:

\[
a\cdot(c\times b)
=
-a\cdot(b\times c).
\]

Thus:

\[
\boxed{
\text{exchange any two inputs}
\Rightarrow
\text{negate the triple product}.
}
\]

Examples:

\[
a\cdot(b\times c)
=
-
b\cdot(a\times c),
\]

and:

\[
=
-
a\cdot(c\times b).
\]

This sign sensitivity is why the quantity is useful as an **orientation predicate** later.

---

# 548.8 If two inputs are equal

Suppose:

\[
b=c.
\]

Then:

\[
b\times c=b\times b=0.
\]

Therefore:

\[
a\cdot(b\times b)=0.
\]

More generally, if the three vectors are linearly dependent, the scalar triple product is zero.

Why?

If:

\[
a=\alpha b+\beta c,
\]

then:

\[
a\cdot(b\times c)
=
(\alpha b+\beta c)\cdot(b\times c).
\]

Distribute:

\[
=
\alpha\, b\cdot(b\times c)
+
\beta\, c\cdot(b\times c).
\]

But \(b\times c\) is perpendicular to both \(b\) and \(c\), so both terms vanish:

\[
\boxed{
a\cdot(b\times c)=0.
}
\]

Thus:

\[
\boxed{
a,b,c\text{ coplanar}
\Rightarrow
a\cdot(b\times c)=0.
}
\]

For three vectors in \(\mathbb R^3\), the converse also holds: zero triple product means they fail to span full 3D volume.

---

# 548.9 Three vectors and linear independence

In \(\mathbb R^3\), three vectors are linearly independent exactly when they span all three dimensions.

That is equivalent to them producing nonzero volume.

Therefore:

\[
\boxed{
a,b,c\text{ independent}
\iff
a\cdot(b\times c)\neq0.
}
\]

And:

\[
\boxed{
a,b,c\text{ dependent}
\iff
a\cdot(b\times c)=0.
}
\]

Later determinant theory generalizes this idea beyond 3D.

---

# 548.10 Units

Suppose all three vectors are displacements in metres.

Then:

\[
b\times c
\]

has units:

\[
m^2.
\]

Dot with \(a\), measured in \(m\):

\[
m\cdot m^2=m^3.
\]

So:

\[
\boxed{
a\cdot(b\times c)
}
\]

has volume units.

That dimensional analysis already predicts Part 549.

---

# 548.11 C++ implementation

```cpp
[[nodiscard]]
constexpr float scalarTriple(
    Vec3 a,
    Vec3 b,
    Vec3 c) noexcept
{
    return dot(a, cross(b, c));
}
```

That version directly mirrors the mathematical definition.

An explicitly expanded version would be:

```cpp
[[nodiscard]]
constexpr float scalarTripleExpanded(
    Vec3 a,
    Vec3 b,
    Vec3 c) noexcept
{
    return
          a.x * (b.y * c.z - b.z * c.y)
        + a.y * (b.z * c.x - b.x * c.z)
        + a.z * (b.x * c.y - b.y * c.x);
}
```

The first form is usually easier to reason about.

The compiler can inline `dot` and `cross`.

---

# 548.12 Numerical danger near coplanarity

Suppose the three vectors are *almost* coplanar.

Then:

\[
a\cdot(b\times c)
\]

is very small relative to the magnitudes of its intermediate products.

This creates cancellation sensitivity.

So this is dangerous:

```cpp
if (scalarTriple(a,b,c) == 0.0f)
```

and even:

```cpp
if (std::abs(scalarTriple(a,b,c)) < 1e-6f)
```

is scale-dependent.

Because if every vector is scaled by \(s\):

\[
(sa)\cdot((sb)\times(sc))
=
s^3
a\cdot(b\times c).
\]

The triple product scales cubically.

A threshold therefore has volume units.

Later robust orientation predicates treat this issue much more seriously.

---

# PART 549 — TRIPLE PRODUCT AS SIGNED VOLUME

Now we give the scalar triple product its complete geometric meaning.

---

# 549.1 Build a parallelepiped

Take vectors:

\[
b,c.
\]

They form a parallelogram base.

Add a third vector:

\[
a.
\]

Extrude the base through displacement \(a\).

The resulting 3D solid is a **parallelepiped**.

A rectangular box is one special case.

In general the edges can be skewed.

Conceptually:

```text
          ●────────●
         /|       /|
        / |      / |
       ●────────●  |
       |  ●─────|──●
       | /      | /
       |/       |/
       ●────────●
```

Its volume is:

\[
\text{base area}\times\text{perpendicular height}.
\]

---

# 549.2 Base area

From Part 545:

\[
\|b\times c\|
\]

is the area of the parallelogram spanned by \(b,c\).

Let:

\[
n=
\frac{b\times c}{\|b\times c\|}
\]

be the unit normal, assuming \(b,c\) are nonparallel.

Then the signed perpendicular component of \(a\) along this normal is:

\[
a\cdot n.
\]

Therefore signed volume is:

\[
V_{\text{signed}}
=
\|b\times c\|
(a\cdot n).
\]

Substitute \(n\):

\[
=
\|b\times c\|
\left[
a\cdot
\frac{b\times c}
{\|b\times c\|}
\right].
\]

Cancel the norm:

\[
\boxed{
V_{\text{signed}}
=
a\cdot(b\times c).
}
\]

That is the geometric derivation.

---

# 549.3 Ordinary volume versus signed volume

Physical volume is nonnegative.

So:

\[
\boxed{
V=
\left|
a\cdot(b\times c)
\right|.
}
\]

But the triple product itself preserves orientation:

\[
\boxed{
V_{\text{signed}}
=
a\cdot(b\times c).
}
\]

Thus the scalar stores two things:

```text
magnitude → volume
sign      → orientation
```

That sign is enormously useful.

---

# 549.4 What does positive versus negative mean?

First choose an orientation convention.

Suppose:

\[
b\times c
\]

points according to the right-hand rule.

If \(a\) has a component in the same direction as \(b\times c\), then:

\[
a\cdot(b\times c)>0.
\]

If \(a\) points to the opposite side of the \(bc\)-plane:

\[
a\cdot(b\times c)<0.
\]

If \(a\) lies within the plane:

\[
a\cdot(b\times c)=0.
\]

So the sign classifies which side of an oriented plane the third vector occupies.

---

# 549.5 Standard basis example

Take:

\[
a=e_z,
\]

\[
b=e_x,
\]

\[
c=e_y.
\]

Then:

\[
b\times c
=
e_x\times e_y
=
e_z.
\]

Thus:

\[
a\cdot(b\times c)
=
e_z\cdot e_z
=
1.
\]

Signed volume:

\[
+1.
\]

Now replace:

\[
a=-e_z.
\]

Then:

\[
(-e_z)\cdot e_z=-1.
\]

Same physical volume:

\[
1.
\]

Opposite orientation.

---

# 549.6 Why changing input order flips orientation but not physical volume

Earlier:

\[
a\cdot(b\times c)
=
-
a\cdot(c\times b).
\]

Taking absolute values:

\[
|V|=|-V|.
\]

So:

\[
\boxed{
\text{permutation can change signed orientation while preserving physical volume}.
}
\]

Exactly as triangle winding flips its normal while preserving triangle area.

This is the 3D analogue.

---

# 549.7 Coplanarity test

If:

\[
V_{\text{signed}}=0,
\]

then the parallelepiped has zero volume.

That means:

\[
a,b,c
\]

lie within a common plane or are otherwise linearly dependent.

So scalar triple product is an algebraic test for coplanarity.

Given four points:

\[
P_0,P_1,P_2,P_3,
\]

construct:

\[
a=P_1-P_0,
\]

\[
b=P_2-P_0,
\]

\[
c=P_3-P_0.
\]

Then:

\[
a\cdot(b\times c)
\]

tests whether the four points lie in the same plane.

This becomes an orientation primitive later in geometry.

---

# 549.8 Tetrahedron volume

A parallelepiped can be decomposed into six equal-volume tetrahedra.

Therefore the tetrahedron formed by one origin and endpoints of \(a,b,c\) has volume:

\[
\boxed{
V_{\text{tetra}}
=
\frac16
\left|
a\cdot(b\times c)
\right|.
}
\]

And signed tetrahedral volume:

\[
\boxed{
V_{\text{tetra,signed}}
=
\frac16
a\cdot(b\times c).
}
\]

The curriculum later gives signed tetrahedral volume its own computational-geometry treatment; for now this is the direct consequence of the triple product.

---

# 549.9 Worked volume example

Take:

\[
b=(3,0,0),
\]

\[
c=(0,4,0),
\]

\[
a=(0,0,5).
\]

First:

\[
b\times c=(0,0,12).
\]

Then:

\[
a\cdot(b\times c)
=
(0,0,5)\cdot(0,0,12)
=
60.
\]

Thus:

\[
\boxed{
V_{\text{parallelepiped}}=60.
}
\]

This is simply:

\[
3\times4\times5=60.
\]

Tetrahedron volume:

\[
\frac{60}{6}=10.
\]

---

# 549.10 Skew example

Let:

\[
b=(2,0,0),
\]

\[
c=(1,3,0),
\]

\[
a=(4,2,5).
\]

Base cross:

\[
b\times c
=
(0,0,6).
\]

Base area:

\[
6.
\]

Although \(a\) has X and Y components, only its perpendicular Z component contributes to height.

Dot:

\[
(4,2,5)\cdot(0,0,6)=30.
\]

Thus:

\[
\boxed{V=30}.
\]

Geometrically:

\[
base=6,
\qquad
height=5,
\]

so:

\[
6\times5=30.
\]

The horizontal part of \(a\) merely shears the solid; it does not change volume.

That observation will later become a fundamental determinant property.

---

# 549.11 Scale behavior

If:

\[
a\rightarrow sa,
\]

then volume scales by:

\[
|s|.
\]

If all three vectors scale by \(s\):

\[
V\rightarrow|s|^3V.
\]

This matches ordinary physical scaling:

```text
length scales by s
area   scales by s²
volume scales by s³
```

This is an excellent dimensional sanity check.

---

# PART 550 — VECTOR TRIPLE-PRODUCT IDENTITY

Now the name becomes dangerous.

The **scalar triple product** was:

\[
a\cdot(b\times c)
\]

and returns a scalar.

The **vector triple product** is something like:

\[
a\times(b\times c)
\]

and returns a vector.

They are very different.

---

# 550.1 The identity

The central result is:

\[
\boxed{
a\times(b\times c)
=
b(a\cdot c)
-
c(a\cdot b).
}
\]

This is often remembered through:

> BAC − CAB

because the output involves vectors \(b\) and \(c\):

\[
\boxed{
b(a\cdot c)-c(a\cdot b).
}
\]

Use the mnemonic only after you understand why the result must live in the plane spanned by \(b,c\).

---

# 550.2 First geometric observation

Let:

\[
n=b\times c.
\]

Then:

\[
n
\]

is perpendicular to both \(b,c\).

Now:

\[
a\times n
\]

must be perpendicular to \(n\).

But the plane perpendicular to \(n\) is exactly the plane spanned by \(b,c\), assuming they are independent.

Therefore:

\[
\boxed{
a\times(b\times c)
\in
\operatorname{span}\{b,c\}.
}
\]

That alone tells us the answer must have form:

\[
\alpha b+\beta c.
\]

This is why the final identity contains only \(b\) and \(c\).

---

# 550.3 Full coordinate derivation

Let:

\[
d=b\times c.
\]

Then:

\[
d_x=b_yc_z-b_zc_y,
\]

\[
d_y=b_zc_x-b_xc_z,
\]

\[
d_z=b_xc_y-b_yc_x.
\]

Now:

\[
a\times d.
\]

Its X component is:

\[
a_yd_z-a_zd_y.
\]

Substitute:

\[
=
a_y(b_xc_y-b_yc_x)
-
a_z(b_zc_x-b_xc_z).
\]

Expand:

\[
=
a_yb_xc_y
-
a_yb_yc_x
-
a_zb_zc_x
+
a_zb_xc_z.
\]

Group terms involving \(b_x\):

\[
=
b_x(a_yc_y+a_zc_z)
-
c_x(a_yb_y+a_zb_z).
\]

Now add and subtract the missing \(a_xb_xc_x\) appropriately through the dot expressions:

\[
b_x(a\cdot c)-c_x(a\cdot b).
\]

Indeed:

\[
b_x(a\cdot c)
=
b_xa_xc_x+b_xa_yc_y+b_xa_zc_z,
\]

while:

\[
c_x(a\cdot b)
=
c_xa_xb_x+c_xa_yb_y+c_xa_zb_z.
\]

The \(a_xb_xc_x\) terms cancel because scalar multiplication commutes.

Thus X component is:

\[
b_x(a\cdot c)-c_x(a\cdot b).
\]

The same expansion gives:

\[
Y=b_y(a\cdot c)-c_y(a\cdot b),
\]

and:

\[
Z=b_z(a\cdot c)-c_z(a\cdot b).
\]

Therefore:

\[
\boxed{
a\times(b\times c)
=
b(a\cdot c)-c(a\cdot b).
}
\]

Derived.

---

# 550.4 Why nested cross products are not associative

If cross were associative, we would have:

\[
a\times(b\times c)
=
(a\times b)\times c.
\]

But the identities differ.

We just proved:

\[
\boxed{
a\times(b\times c)
=
b(a\cdot c)
-
c(a\cdot b).
}
\]

For the other grouping:

\[
\boxed{
(a\times b)\times c
=
b(a\cdot c)
-
a(b\cdot c).
}
\]

Different second term.

Therefore:

\[
\boxed{
(a\times b)\times c
\neq
a\times(b\times c)
}
\]

in general.

Parentheses in chained cross products are mandatory conceptually.

---

# 550.5 Derive the second form

Use anti-commutativity:

\[
(a\times b)\times c
=
-
c\times(a\times b).
\]

Apply BAC−CAB to:

\[
c\times(a\times b):
\]

\[
=
a(c\cdot b)-b(c\cdot a).
\]

Negate:

\[
=
-a(c\cdot b)+b(c\cdot a).
\]

Dot symmetry:

\[
c\cdot b=b\cdot c,
\]

\[
c\cdot a=a\cdot c.
\]

Therefore:

\[
\boxed{
(a\times b)\times c
=
b(a\cdot c)
-
a(b\cdot c).
}
\]

---

# 550.6 Worked example

Take:

\[
a=(1,2,3),
\]

\[
b=(2,0,1),
\]

\[
c=(0,1,0).
\]

First calculate:

\[
b\times c.
\]

\[
(2,0,1)\times(0,1,0)
=
(-1,0,2).
\]

Then:

\[
a\times(b\times c)
=
(1,2,3)\times(-1,0,2).
\]

X:

\[
2(2)-3(0)=4.
\]

Y:

\[
3(-1)-1(2)=-5.
\]

Z:

\[
1(0)-2(-1)=2.
\]

So:

\[
\boxed{(4,-5,2)}.
\]

Now verify the identity.

\[
a\cdot c
=
2.
\]

\[
a\cdot b
=
1(2)+2(0)+3(1)
=
5.
\]

Thus:

\[
b(a\cdot c)-c(a\cdot b)
\]

\[
=
2b-5c
\]

\[
=
2(2,0,1)-5(0,1,0)
\]

\[
=
(4,0,2)-(0,5,0)
\]

\[
=
\boxed{(4,-5,2)}.
\]

Exact match.

---

# 550.7 A very important special identity

Let:

\[
c=a.
\]

Then:

\[
a\times(b\times a)
=
b(a\cdot a)-a(a\cdot b).
\]

Since:

\[
a\cdot a=\|a\|^2,
\]

we get:

\[
\boxed{
a\times(b\times a)
=
\|a\|^2b-(a\cdot b)a.
}
\]

If \(a\) is unit:

\[
\|a\|^2=1,
\]

then:

\[
\boxed{
a\times(b\times a)
=
b-(a\cdot b)a.
}
\]

Look familiar?

From Part 539, for unit \(a\):

\[
\operatorname{rej}_a b
=
b-(b\cdot a)a.
\]

Dot symmetry gives:

\[
b\cdot a=a\cdot b.
\]

So:

\[
\boxed{
a\times(b\times a)
=
\operatorname{rej}_a b
}
\]

when \(a\) is unit.

That is a beautiful connection:

**a particular double-cross operation extracts the component of \(b\) perpendicular to \(a\).**

---

# 550.8 Cross-cross versus projection

Using the non-unit version:

\[
a\times(b\times a)
=
\|a\|^2b-(a\cdot b)a.
\]

Divide by:

\[
\|a\|^2
\]

for nonzero \(a\):

\[
\frac{
a\times(b\times a)
}{
\|a\|^2
}
=
b-
\frac{a\cdot b}{a\cdot a}a.
\]

Right side is exactly:

\[
\boxed{
\operatorname{rej}_a b.
}
\]

Thus:

\[
\boxed{
\operatorname{rej}_a b
=
\frac{
a\times(b\times a)
}{
\|a\|^2
}.
}
\]

Projection and cross-product algebra are deeply connected.

---

# 550.9 Why would we ever expand a nested cross?

The expanded form can:

- expose which vector space the result lies in;
- simplify symbolic derivations;
- remove nested cross computations;
- expose projection/rejection structure;
- help prove geometric identities.

But mechanically replacing all nested crosses with BAC−CAB is not necessarily faster or clearer.

Use the representation that best communicates the intended geometry.

---

# 550.10 C++ implementation

Normally:

```cpp
Vec3 result = cross(a, cross(b, c));
```

is already clear.

Equivalent expanded form:

```cpp
Vec3 result =
    b * dot(a, c)
  - c * dot(a, b);
```

A good test suite should verify these approximately agree for many finite inputs.

# PART 551 — ANGLES BETWEEN VECTORS

We derived the cosine relation in Part 536.

Now we make **angle computation itself** the object of study.

---

# 551.1 What exactly is "the angle between two vectors"?

Two nonzero vectors define two directions.

The ordinary **unsigned principal angle** between them is conventionally:

\[
\boxed{
\theta\in[0,\pi].
}
\]

That means:

\[
0^\circ\le\theta\le180^\circ.
\]

This angle answers how far one direction differs from the other without specifying a clockwise/counterclockwise orientation around some axis.

Examples:

\[
\theta=0
\]

same direction.

\[
\theta=\frac{\pi}{2}
\]

perpendicular.

\[
\theta=\pi
\]

opposite.

---

# 551.2 Why the angle is undefined for zero vectors

Angle is a relationship between **directions**.

But:

\[
0
\]

has no direction.

The standard cosine expression:

\[
\cos\theta
=
\frac{
a\cdot b
}{
\|a\|\|b\|
}
\]

contains division by zero if either magnitude is zero.

This is not merely an implementation nuisance.

There genuinely is no orientation to compare.

Therefore:

\[
\boxed{
\theta(a,b)
\text{ requires }
a\neq0,\;b\neq0.
}
\]

---

# 551.3 The familiar `acos` formula

From Part 536:

\[
a\cdot b
=
\|a\|\|b\|\cos\theta.
\]

Therefore:

\[
\cos\theta
=
\frac{
a\cdot b
}{
\|a\|\|b\|
}.
\]

Apply inverse cosine:

\[
\boxed{
\theta
=
\arccos
\left(
\frac{
a\cdot b
}{
\|a\|\|b\|
}
\right).
}
\]

This is mathematically correct for nonzero vectors.

---

# 551.4 Unit-vector case

If:

\[
\|a\|=\|b\|=1,
\]

then:

\[
\boxed{
\theta=\arccos(a\cdot b).
}
\]

This is why many graphics APIs assume normalized direction vectors before angular calculations.

But production code still needs to account for floating-point drift.

---

# 551.5 Worked example

Take:

\[
a=(1,0)
\]

and:

\[
b=(1,1).
\]

Dot:

\[
a\cdot b=1.
\]

Magnitudes:

\[
\|a\|=1,
\]

\[
\|b\|=\sqrt2.
\]

Therefore:

\[
\cos\theta
=
\frac1{\sqrt2}.
\]

So:

\[
\boxed{
\theta
=
\frac{\pi}{4}
=
45^\circ.
}
\]

---

# 551.6 Radians versus degrees

Most mathematical and standard-library trigonometric functions use **radians**.

A full turn is:

\[
2\pi\text{ radians}=360^\circ.
\]

Thus:

\[
\pi=180^\circ,
\]

\[
\frac{\pi}{2}=90^\circ,
\]

\[
\frac{\pi}{4}=45^\circ.
\]

Conversion:

\[
\boxed{
degrees
=
radians\frac{180}{\pi}
}
\]

and:

\[
\boxed{
radians
=
degrees\frac{\pi}{180}.
}
\]

Engine APIs should ideally make angular units explicit rather than letting a naked `float` ambiguously mean degrees or radians.

---

# 551.7 Angle does not care about vector magnitude

Scale by positive values:

\[
a'=sa,\qquad b'=tb,
\]

where:

\[
s,t>0.
\]

Then:

\[
\frac{
a'\cdot b'
}{
\|a'\|\|b'\|
}
=
\frac{
st(a\cdot b)
}{
s\|a\|t\|b\|
}
\]

so all scale cancels:

\[
=
\frac{a\cdot b}{\|a\|\|b\|}.
\]

Therefore the angle is unchanged.

Makes sense:

```text
(1,0)
(1000,0)
```

have the same direction.

---

# 551.8 What if one vector is multiplied by a negative scalar?

If:

\[
a'=-a,
\]

its direction reverses.

If original angle is:

\[
\theta,
\]

the new principal angle becomes:

\[
\boxed{
\pi-\theta.
}
\]

Because:

\[
(-a)\cdot b
=
-(a\cdot b),
\]

so:

\[
\cos\theta'
=
-\cos\theta
=
\cos(\pi-\theta).
\]

Thus negative scaling changes directional orientation.

---

# 551.9 You often don't need the angle

Actual angle computation is frequently unnecessary.

Suppose you only want:

> Are these unit directions within \(30^\circ\)?

Precompute:

\[
c=\cos30^\circ.
\]

Because cosine decreases over:

\[
[0,\pi],
\]

we have:

\[
\theta\le30^\circ
\iff
a\cdot b\ge c.
\]

So:

```cpp
if (dot(unitForward, unitToTarget) >= cosHalfFov) {
    // Target is inside the angular cone.
}
```

This avoids inverse trigonometry entirely.

If the only required result is classification, do not calculate more than the classification needs.

---

# 551.10 The numerical problem with `acos`

The derivative is:

\[
\frac{d}{dx}\arccos x
=
-\frac1{\sqrt{1-x^2}}.
\]

Look at the denominator.

As:

\[
x\rightarrow1
\]

or:

\[
x\rightarrow-1,
\]

we get:

\[
1-x^2\rightarrow0.
\]

Therefore the derivative magnitude becomes very large.

Interpretation:

\[
\boxed{
\arccos
\text{ is numerically sensitive when vectors are nearly parallel or antiparallel}.
}
\]

A tiny error in cosine can cause disproportionately larger angle error near:

\[
0
\]

or:

\[
\pi.
\]

This is exactly why Part 552 exists.

---

# 551.11 Floating-point domain overshoot

Mathematically:

\[
-1\le
\frac{a\cdot b}{\|a\|\|b\|}
\le1.
\]

Floating point may produce:

\[
1.0000001
\]

for theoretically parallel vectors.

Then:

```cpp
std::acos(1.0000001f)
```

is outside the mathematical domain.

Result may be NaN.

Therefore a conventional implementation clamps:

```cpp
float cosine =
    dot(a, b) /
    (length(a) * length(b));

cosine =
    std::clamp(cosine, -1.0f, 1.0f);

float angle =
    std::acos(cosine);
```

But this still retains `acos`'s conditioning near the endpoints.

---

# 551.12 Naive implementation and its preconditions

```cpp
[[nodiscard]]
float angleBetweenAcos(
    Vec3 a,
    Vec3 b)
{
    const float aa = dot(a, a);
    const float bb = dot(b, b);

    if (aa == 0.0f || bb == 0.0f) {
        throw std::domain_error(
            "Angle undefined for zero vector");
    }

    const float denominator =
        std::sqrt(aa * bb);

    float cosine =
        dot(a, b) / denominator;

    cosine =
        std::clamp(cosine, -1.0f, 1.0f);

    return std::acos(cosine);
}
```

Even this code has another issue:

\[
aa\cdot bb
\]

can overflow for huge magnitudes or underflow for tiny ones.

So production numerical code needs stronger care.

---

# PART 552 — ROBUST ANGLE COMPUTATION WITH `atan2`

This is the production payoff of the entire dot/cross sequence.

Instead of reconstructing the angle using cosine alone, use **both** sine-like and cosine-like information.

---

# 552.1 What information do dot and cross provide?

For nonzero vectors:

\[
a\cdot b
=
\|a\|\|b\|\cos\theta.
\]

And from Part 545:

\[
\|a\times b\|
=
\|a\|\|b\|\sin\theta.
\]

Define:

\[
x=a\cdot b,
\]

\[
y=\|a\times b\|.
\]

Then:

\[
x=K\cos\theta,
\]

\[
y=K\sin\theta,
\]

where:

\[
K=\|a\|\|b\|>0.
\]

So the pair:

\[
(x,y)
\]

is proportional to:

\[
(\cos\theta,\sin\theta).
\]

That is exactly the information `atan2` wants.

---

# 552.2 What `atan2` does

Conceptually:

\[
\operatorname{atan2}(y,x)
\]

returns the angle corresponding to a 2D vector with Cartesian coordinates:

\[
(x,y).
\]

Unlike ordinary:

\[
\arctan\left(\frac yx\right),
\]

`atan2` examines the signs of both \(x\) and \(y\), so it can determine the correct quadrant.

This is crucial.

For example:

\[
\frac{1}{1}=1
\]

and:

\[
\frac{-1}{-1}=1.
\]

Plain `atan(1)` cannot distinguish the first quadrant from the third.

`atan2` can.

---

# 552.3 Derive the robust vector-angle formula

We know:

\[
x=
a\cdot b
=
K\cos\theta,
\]

and:

\[
y=
\|a\times b\|
=
K\sin\theta.
\]

Then:

\[
\operatorname{atan2}(y,x)
=
\operatorname{atan2}
(
K\sin\theta,
K\cos\theta
).
\]

Since:

\[
K>0,
\]

common positive scaling does not change the angle.

Therefore:

\[
\boxed{
\theta
=
\operatorname{atan2}
\left(
\|a\times b\|,
a\cdot b
\right)
}
\]

for nonzero vectors in \(\mathbb R^3\).

Because:

\[
\|a\times b\|\ge0,
\]

the resulting unsigned angle lies in:

\[
\boxed{
[0,\pi].
}
\]

Exactly the principal angle we want.

---

# 552.4 Why normalization is unnecessary mathematically

Notice both arguments contain the same factor:

\[
\|a\|\|b\|.
\]

Thus vector magnitudes cancel conceptually inside the angle.

We do not need to normalize first:

\[
\boxed{
\theta
=
\operatorname{atan2}
(
\|a\times b\|,
a\cdot b
).
}
\]

This can avoid two explicit normalization operations and their divide-by-small-value concerns.

Zero vectors remain invalid because then both dot and cross information collapse.

---

# 552.5 Same direction

If vectors point identically:

\[
\theta=0.
\]

Then:

\[
\|a\times b\|=0,
\]

and:

\[
a\cdot b>0.
\]

So:

\[
\operatorname{atan2}(0,\text{positive})
=
0.
\]

Correct.

---

# 552.6 Opposite direction

If:

\[
\theta=\pi,
\]

then:

\[
\|a\times b\|=0,
\]

but:

\[
a\cdot b<0.
\]

Thus:

\[
\operatorname{atan2}(0,\text{negative})
=
\pi
\]

under the intended principal-angle convention.

This is an important advantage over trying to recover angle from:

\[
\tan\theta
=
\frac{\|a\times b\|}{a\cdot b}.
\]

The ratio alone would be zero for both \(0^\circ\) and \(180^\circ\).

`atan2` uses the sign of the dot to distinguish them.

---

# 552.7 Perpendicular

If:

\[
a\cdot b=0
\]

and vectors are nonzero/perpendicular, then:

\[
\|a\times b\|>0.
\]

Therefore:

\[
\operatorname{atan2}(\text{positive},0)
=
\frac\pi2.
\]

Correct.

---

# 552.8 Worked \(45^\circ\) example

Take:

\[
a=(1,0,0),
\]

\[
b=(1,1,0).
\]

Dot:

\[
a\cdot b=1.
\]

Cross:

\[
a\times b=(0,0,1).
\]

Cross magnitude:

\[
1.
\]

Therefore:

\[
\theta=
\operatorname{atan2}(1,1).
\]

Thus:

\[
\boxed{
\theta=\frac\pi4=45^\circ.
}
\]

No normalization needed.

---

# 552.9 Worked obtuse example

Take:

\[
a=(1,0,0)
\]

and:

\[
b=(-1,1,0).
\]

Dot:

\[
-1.
\]

Cross:

\[
(0,0,1).
\]

Magnitude:

\[
1.
\]

Thus:

\[
\theta=
\operatorname{atan2}(1,-1)
=
\frac{3\pi}{4}.
\]

Therefore:

\[
\boxed{
135^\circ.
}
\]

The negative dot automatically selects the obtuse quadrant.

---

# 552.10 Why this tends to be more robust than `acos`

With `acos`, we compress all angular information into:

\[
\cos\theta.
\]

Near:

\[
\theta=0,
\]

cosine changes very slowly:

\[
\cos\theta
\approx
1-\frac{\theta^2}{2}.
\]

So tiny angular differences become **second-order changes** near 1.

For example:

\[
\theta=10^{-4}.
\]

Then approximately:

\[
1-\cos\theta
\approx
\frac{10^{-8}}2
=
5\times10^{-9}.
\]

That tiny difference can be difficult to resolve in limited precision.

By contrast:

\[
\sin\theta
\approx\theta
\]

for small \(\theta\).

The cross magnitude therefore carries a **first-order** signal of the small angle.

`atan2` uses both:

\[
\sin\theta
\]

and:

\[
\cos\theta,
\]

so small angular deviations can remain better represented.

That is the key robustness reason.

---

# 552.11 Near \(\pi\)

Let:

\[
\theta=\pi-\varepsilon
\]

for tiny \(\varepsilon\).

Then:

\[
\cos\theta
=
-\cos\varepsilon
\approx
-1+\frac{\varepsilon^2}{2}.
\]

Again cosine differs from \(-1\) only quadratically.

But:

\[
\sin(\pi-\varepsilon)
=
\sin\varepsilon
\approx
\varepsilon.
\]

So cross magnitude again gives a first-order measure of departure from exact antiparallelism.

This is why `atan2` remains attractive near both troublesome endpoints of `acos`.

---

# 552.12 The formula is not magically immune to floating-point overflow

Be careful.

Directly compute:

\[
a\times b
\]

with enormous vectors, and component products can overflow.

Likewise:

\[
a\cdot b
\]

can overflow.

So:

```cpp
atan2(length(cross(a,b)), dot(a,b))
```

is not automatically numerically bulletproof for arbitrarily scaled floating-point inputs.

The formula improves **angular conditioning**, but input scaling still matters.

---

# 552.13 Scale both inputs safely

Because angle is invariant under positive scaling, we can scale the vectors before dot/cross.

For each vector, choose:

\[
s_a=
\max(|a_x|,|a_y|,|a_z|),
\]

\[
s_b=
\max(|b_x|,|b_y|,|b_z|).
\]

If either is zero, angle is undefined.

Otherwise define:

\[
a'=\frac a{s_a},
\]

\[
b'=\frac b{s_b}.
\]

Now all components have magnitude at most 1.

The angle is unchanged because:

\[
a'=k_a a,
\qquad
b'=k_b b
\]

for positive \(k_a,k_b\).

Thus use:

\[
\boxed{
\theta=
\operatorname{atan2}
(
\|a'\times b'\|,
a'\cdot b'
).
}
\]

This greatly reduces overflow/underflow risk in intermediate products.

---

# 552.14 Robust reference implementation

```cpp
#include <algorithm>
#include <cmath>
#include <optional>

[[nodiscard]]
std::optional<double>
angleBetween(Vec3d a, Vec3d b) noexcept
{
    if (!std::isfinite(a.x) ||
        !std::isfinite(a.y) ||
        !std::isfinite(a.z) ||
        !std::isfinite(b.x) ||
        !std::isfinite(b.y) ||
        !std::isfinite(b.z))
    {
        return std::nullopt;
    }

    const double scaleA =
        std::max({
            std::abs(a.x),
            std::abs(a.y),
            std::abs(a.z)
        });

    const double scaleB =
        std::max({
            std::abs(b.x),
            std::abs(b.y),
            std::abs(b.z)
        });

    if (scaleA == 0.0 ||
        scaleB == 0.0)
    {
        return std::nullopt;
    }

    a = a / scaleA;
    b = b / scaleB;

    const Vec3d c = cross(a, b);

    const double sineLike =
        std::hypot(c.x, c.y, c.z);

    const double cosineLike =
        dot(a, b);

    return std::atan2(
        sineLike,
        cosineLike
    );
}
```

The names:

```cpp
sineLike
cosineLike
```

are deliberate.

They are not necessarily:

\[
\sin\theta,\cos\theta
\]

individually because the scaled vectors are not necessarily unit.

Rather:

\[
sineLike=K\sin\theta,
\]

\[
cosineLike=K\cos\theta.
\]

The same positive factor \(K\) cancels inside `atan2`.

---

# 552.15 Why `std::hypot` for the cross length?

Naively:

```cpp
sqrt(c.x*c.x + c.y*c.y + c.z*c.z)
```

can itself overflow or underflow.

`std::hypot` is intended to calculate Euclidean hypotenuse/norm more robustly.

Since the cross components have already been bounded substantially by pre-scaling the input vectors, risk is already reduced, but robust length computation is still sensible when numerical range matters.

---

# 552.16 Signed angle needs more information

Our formula:

\[
\operatorname{atan2}
(
\|a\times b\|,
a\cdot b
)
\]

uses:

\[
\|a\times b\|\ge0.
\]

So it intentionally discards cross orientation.

It returns an **unsigned** angle:

\[
[0,\pi].
\]

In 3D, asking:

> Is the turn clockwise or counterclockwise?

is incomplete unless you specify an orientation axis or plane normal.

Given a chosen unit reference axis \(n\), a common oriented quantity is:

\[
n\cdot(a\times b).
\]

Then a signed planar angle around \(n\) can be expressed conceptually as:

\[
\boxed{
\theta_{\text{signed}}
=
\operatorname{atan2}
\left(
n\cdot(a\times b),
a\cdot b
\right)
}
\]

when \(a,b\) are interpreted in the plane perpendicular to \(n\).

That yields sign information from the oriented cross product.

The curriculum later gives orientation tests their own Parts, so the important point here is simply that **signed 3D angle requires a chosen orientation axis**.

---

# DOT + CROSS + ATAN2: THE COMPLETE ANGULAR SYSTEM

You should now see the full relationship:

\[
\boxed{
a\cdot b
=
\|a\|\|b\|\cos\theta
}
\]

and:

\[
\boxed{
\|a\times b\|
=
\|a\|\|b\|\sin\theta.
}
\]

Therefore:

\[
\boxed{
\theta=
\operatorname{atan2}
(
\|a\times b\|,
a\cdot b
).
}
\]

This is much deeper than:

> use `atan2` because it is more accurate.

You now know **why**.

The dot tracks cosine-like parallel alignment.

The cross tracks sine-like perpendicular separation.

`atan2` reconstructs the quadrant-aware angle from both.

# PRODUCTION FAILURE MODES

The hardest failures in this block are not syntax errors. They are semantic and numerical.

For scalar triple product, a tiny value may mean true coplanarity or merely near-coplanarity plus floating-point cancellation. Because the quantity has cubic scale, one universal epsilon is not meaningful.

For the vector triple product, missing parentheses can silently change the mathematics because the cross product is not associative.

For angle computation, zero vectors make the mathematical angle undefined. `acos` requires clamping because floating-point cosine estimates can drift outside \([-1,1]\), while `atan2` avoids that domain clamp but can still overflow or underflow if dot/cross intermediates are badly scaled.

And for every operation here, all vectors must live in compatible coordinate spaces. A triple product involving local-, world-, and view-space vectors is merely arithmetic on unrelated coordinates, not geometry.

---

# HARDWARE / COST

For fixed `Vec3`, everything here is constant-time.

A scalar triple product is one cross plus one dot: roughly a handful of multiplies/adds/subtracts.

A vector triple product may be evaluated as two crosses or as two dots, two vector scales, and a subtraction after algebraic expansion. Which is faster depends on target hardware, SIMD layout, compiler optimization, surrounding reuse, and whether intermediate dot/cross results are already available.

Angle computation is much more expensive than a raw dot or cross because transcendental operations such as `acos`/`atan2` are substantially heavier arithmetic kernels. Consequently, gameplay/graphics tests that only need a cone threshold should usually compare dot values rather than calculating an angle.

As always, profiling beats folklore.
