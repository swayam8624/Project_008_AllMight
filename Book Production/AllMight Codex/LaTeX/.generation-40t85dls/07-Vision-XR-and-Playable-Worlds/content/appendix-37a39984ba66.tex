\section{Vector value types and component access}\label{appendix-37a39984ba66-vector-value-types-and-component-access}

\hypertarget{appendix-37a39984ba66-vector-value-types-and-component-access}{}

\textbf{Curriculum depth:} Introduced · \textbf{First seen:} Phase6 · \textbf{Latest development:} Phase6

\begin{allmightroledefinition}

\subsection{Definition and mechanism}\label{appendix-37a39984ba66-definition-and-mechanism}

\hypertarget{appendix-37a39984ba66-definition-and-mechanism}{}

A vector value type stores components directly with coherent arithmetic and initialization. Named members are not an array. Named dot, cross and Hadamard operations avoid ambiguous vector multiplication; writable swizzles need explicit alias policies.

\end{allmightroledefinition}

A checked component accessor selects one of three real members and rejects out-of-range indices. It does not traverse from the address of the first member.
