\section{Placement construction and explicit lifetime management}\label{appendix-f56c3e43fd4e-placement-construction-and-explicit-lifetime-management}

\hypertarget{appendix-f56c3e43fd4e-placement-construction-and-explicit-lifetime-management}{}

\begin{allmightroledefinition}

\subsection{Definition and mechanism}\label{appendix-f56c3e43fd4e-definition-and-mechanism}

\hypertarget{appendix-f56c3e43fd4e-definition-and-mechanism}{}

Placement new or \BookInlineCode{std::construct\_at} initializes an object in storage already provided by the caller; it does not allocate that backing storage. The storage must have adequate size and alignment. \BookInlineCode{std::destroy\_at} ends an object's lifetime but does not release the storage. A pool/container must track occupancy, partial construction, exactly-once destruction, and when reuse is permitted. Transparent replacement and \BookInlineCode{std::launder} have detailed preconditions; launder neither constructs nor revives an object.

\end{allmightroledefinition}
