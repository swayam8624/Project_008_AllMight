Direct tile counting versus Maveb’s Gaussian counting

There are two broad constructions.

A traditional tile-centric approach first counts:

c o u n t [ t ] = number of Gaussians touching tile  t .

Then scan tile counts.

Maveb instead counts:

c o u n t [ g ] = number of tiles touched by Gaussian  g .

Then scans Gaussian counts to allocate one contiguous output region per Gaussian.

After all references are generated, it sorts them by tile and depth.

Both approaches ultimately produce:

tile → ordered Gaussian references .

Maveb’s approach is especially natural because every projection thread already knows the entire tile rectangle of its Gaussian.

We now know how many references each Gaussian emits:

Suppose foreground A:

C A , α A

and background B:

C B , α B .

A over B gives:

C = α A C A + ( 1 − α A ) α B C B .

Reverse:

C ′ = α B C B + ( 1 − α B ) α A C A .

Generally:

C ≠ C ′ .

Therefore alpha blending is not commutative.

Depth order matters.

Concrete example

Red A:

Blue B:

C B = ( 0 , 0 , 1 ) , α B = 0.5 .

A in front:

B in front:

C ′ = ( 0.25 , 0 , 0.5 ) .

Very different.

Sorting is not optional.

One option:

Sort every visible Gaussian globally by depth:

Then each tile can reference Gaussians in that order.

This is conceptually simple.

But if we duplicate a Gaussian across tiles anyway, sorting expanded references can directly produce per-tile contiguous ranges.

Maveb sorts:

That simultaneously groups by tile and orders by depth.

Why per-tile ordering is enough

A pixel only receives Gaussians whose footprints overlap its tile.

Therefore relative ordering of:

G A

in tile 12 and:

G B

in tile 98 is irrelevant.

They can never affect the same pixel.

So a global total ordering contains unnecessary ordering constraints.

The true requirement is:

all splats that may affect the same pixel must be correctly ordered .

Tile-local sort is a conservative way to ensure that.

Suppose two splats have equal depth:

z A = z B .

Their alpha blend order still potentially changes output.

If GPU sorting arbitrarily permutes equal keys each frame, you can get:

  • flickering,
  • nondeterministic captures,
  • CPU/GPU mismatch,
  • difficult debugging.

So sort should be stable.

A stable sort preserves earlier order among equal keys.

Maveb’s stability

References are generated deterministically:

Gaussian index ascending.

Within each Gaussian, tile Y then tile X ascending.

The radix scatter uses prefix ranks preserving input order within each bucket.

Thus equal sort keys preserve initial relative order.

That gives deterministic tie behavior.

This matters much more than it first appears.

Comparison sort costs roughly:

O ( M log ⁡ M ) .

Keys are fixed-width integers.

Radix sort can achieve:

O ( k M )

where k is number of digit passes.

LSD radix sort

Least-significant-digit radix sort processes low-order digit first.

For a multi-component composite key:

if stable sorting is used, sort secondary key first, then primary key.

We want tile primary, depth secondary.

So:

sort depth first → sort tile second .

Because tile sort is stable, depth order inside each tile is preserved.

That is exactly Maveb’s pass ordering.

CPU ORACLE, METAL EXECUTION AND QUANTITATIVE AGREEMENT

Maveb’s CPU oracle first projects all valid Gaussians.

Then:

std::ranges::stable_sort(
    projected,
    {},
    &Projected::depth);

Since reference camera uses:

+ Z

forward and smaller positive Z is closer:

ascending depth = front-to-back .

Stable sort preserves source order for equal depth.

This is deliberately compatible with deterministic GPU ordering.

Why a CPU oracle should be simple

The CPU reference implementation should optimize primarily for:

clarity + determinism + correctness .

Not maximum performance.

If CPU and GPU share the same clever algorithm and same bug, comparison proves nothing.

A useful oracle should be independent enough that implementation mistakes are unlikely to correlate.

Maveb’s CPU rasterizer does not run the GPU’s radix pipeline.

It globally stable-sorts projected records, then rasterizes them.

Good.

Yet CPU still avoids pathological P × N

Maveb partitions the image into horizontal:

16 -row bands .

For each projected Gaussian it computes pixel AABB and inserts a BandEntry into every intersected horizontal band.

Then each band processes only relevant Gaussians.

This is not the exact same 16×16 tile algorithm as GPU.

That difference is useful.

Why deterministic threading survives

Global projected list is already sorted.

Band lists receive Gaussians in that sorted order.

Every band owns disjoint rows.

So threads never concurrently update the same pixel.

Thus:

thread scheduling does not affect pixel accumulation order .

This gives deterministic multi-threaded CPU output.

That is an excellent oracle design.

A CPU implementation could use the same conceptual tile ranges:

for each tile:
{
    const auto [begin,end] =
        ranges[tile];

    for each pixel in tile:
    {
        float T = 1.0f;
        Vec3 color{};

        for (
            reference = begin;
            reference < end;
            ++reference)
        {
            evaluate splat;

            if (outside ellipse)
                continue;

            ...

            if (T < threshold)
                break;
        }
    }
}

This has excellent cache locality because one tile’s Gaussian list is shared by its pixels.

Maveb’s oracle currently uses horizontal bands instead because it is simpler and remains independent from GPU scheduling machinery.

That independence is valuable for validation.

Give captured Gaussians stable world identity

A splat renderer answers an image question: which color and opacity does this primitive contribute at a pixel? Editing a captured scene asks a different question: which persistent world element does this primitive represent, and which physical variables are allowed to move it? These representations overlap, but they are not interchangeable. The original 3D Gaussian Splatting work optimizes anisotropic primitives for view synthesis and rendering; the entity and motion contract below is an explicit engine extension, not a property guaranteed by a trained PLY file. The 3D Gaussian Splatting paper

Keep identity separate from storage order. Let each Gaussian carry an immutable identifier g i = ( n i , ℓ i ) , where n i is a namespace or asset identifier and ℓ i is a local identifier. The current vector index is only a temporary address. Sorting, compaction, filtering, or cloning may change that address; none of those operations may silently change the identity of an existing record. A lookup table maps g i to the current index and is rebuilt after a reorder. A newly cloned primitive receives a new identifier and records its parent ID; it does not reuse the parent’s ID.

An editable scene needs a second relation from Gaussian IDs to semantic entities and physical degrees of freedom. Represent it as a versioned association table. For Gaussian i and entity or node j , let w i j be the authored influence weight. For a Gaussian fully assigned to one rigid object, one weight is 1 . For a soft boundary, several weights may be nonzero. Within one declared support set, require

w i j ≥ 0 , ∑ j w i j = 1.

Normalization is necessary to reproduce a common translation. Reproducing a complete affine map also requires the rest-center reconstruction below, or an explicitly retained local offset. It does not prove that the association is correct: confidence, source, and an unassigned state must remain explicit. Do not turn a low-confidence semantic guess into a collider or a destructive edit automatically.

First consider weights with linear precision: the support positions reproduce the actual learned center, rather than merely averaging some nearby nodes. With associated rest positions x j , this means

μ i = ∑ j w i j x j .

If every support point receives the same affine map x j ′ = A x j + b , then

μ i ′ = ∑ j w i j ( A x j + b ) = A ∑ j w i j x j + b ∑ j w i j = A μ i + b .

The last equality uses ∑ j w i j = 1 . This is the affine-reproduction property: the weighted correspondence follows any shared translation, rotation, scale, or shear exactly. If the weights do not sum to one, even a common translation is scaled incorrectly.

A rigid attachment is not the same as replacing every center by the body’s center of mass. For body center x j and rotation R j , retain each splat’s own local offset r i = R j T ( μ i − x j ) . Its new center is x j ′ + R j ′ r i . A one-weight row says which body owns it; that row alone does not encode its distinct location.

For general support weights that do not reconstruct the learned center, retain d i = μ i − ∑ j w i j x j . Given a declared local affine map A i , use μ i ′ = ∑ j w i j x j ′ + A i d i . Under a common edit x j ′ = A x j + b and A i = A , this still yields A μ i + b . Dropping d i would cause an immediate jump even before any edit. An empty or unreliable association remains explicitly unassigned; it should not be repaired by inventing uniform weights.

A Gaussian’s covariance describes its spatial footprint. Under the same local linear map A , transform it by

Σ i ′ = A Σ i A T .

To derive this, write a centered sample as δ = x − μ with covariance E [ δ δ T ] = Σ . The transformed centered sample is δ ′ = A δ ; therefore

E [ δ ′ δ ′ T ] = E [ A δ δ T A T ] = A Σ A T .

Translation cancels from covariance. A nonsingular A preserves positive definiteness. If A collapses an axis, Σ ′ becomes singular and cannot be inverted to form a conic. A production edit must then reject the update or apply a separately declared minimum-scale policy; silently inverting a singular covariance is not a valid repair. For a pure translation, A = I , so the mean moves and the covariance stays unchanged. For a rigid rotation R , the covariance rotates as R Σ R T . For a uniform scale s , it becomes s 2 Σ .

For a deforming support, estimate a local map only when the neighborhood contains enough independent motion. With centered rest offsets r j = x j − μ and changed offsets r j ′ = x j ′ − μ ′ , a weighted least-squares map minimizes ∑ j w i j ‖ r j ′ − A r j ‖ 2 . If the weighted rest covariance M = ∑ j w i j r j r j T is nonsingular, the solution is

A i = ( ∑ j w i j r j ′ r j T ) M − 1 .

This formula follows by setting the matrix derivative of the squared residual to zero. Solve the resulting linear system with a rank-aware method rather than forming the inverse explicitly in numerical code. It supplies a local affine approximation over this primitive; spatially varying influences or a strongly curved deformation are not represented exactly by one matrix. If M is rank deficient, the neighborhood does not determine a full 3D affine map; use a lower-dimensional model, add a documented regularizer, or reject the deformation. The equation defines a local approximation, not a guarantee that arbitrary cloth folds or topology changes are represented faithfully.

Two support nodes have rest positions x 1 = ( 0 , 0 ) T and x 2 = ( 4 , 2 ) T . A Gaussian uses w 1 = w 2 = 0.5 , so its mean is

μ = 0.5 ( 0 , 0 ) + 0.5 ( 4 , 2 ) = ( 2 , 1 ) .

Apply A = [ 2 0 0 1 ] and b = ( 1 , − 1 ) T . The nodes become x 1 ′ = ( 1 , − 1 ) and x 2 ′ = ( 9 , 1 ) . The weighted mean is ( 5 , 0 ) , which agrees with A μ + b = ( 5 , 0 ) . Now let the original covariance be Σ = [ 4 1 1 2 ] . Then

Σ ′ = A Σ A T = [ 2 0 0 1 ] [ 4 1 1 2 ] [ 2 0 0 1 ] = [ 16 2 2 2 ] .

Here A is supplied as the edit operator; two support nodes alone would not determine an unrestricted two-dimensional affine fit. The determinant changes from 7 to 28 , matching det ( A ) 2 det ( Σ ) = 4 ⋅ 7 . Translation changed the center but contributed nothing to the covariance. Couple edits in both directions and keep their proof

An appearance edit and a physical edit are separate operations with an explicit bridge between them. In one direction, a semantic selection resolves stable entity IDs to stable Gaussian IDs, then maps those Gaussian IDs through the versioned support table to affected physical DOFs. In the other direction, a committed physical state computes the local motion map for each supported Gaussian, updates its mean and covariance, and rebuilds projected bounds and tile references before rendering. A translation need not change an object-attached appearance function in this model. For spherical-harmonic (SH) appearance attached to a frame F , evaluate its coefficients using local viewing direction F T d w o r l d , and rotate F with the object. A renderer that instead stores world-direction coefficients must explicitly choose whether to preserve that world-space function or rotate its basis to follow the object. Deformation and relighting do not have an automatic appearance solution. Keep the appearance frame separate from the covariance eigenbasis: repeated eigenvalues and eigenvector sign choices can change that basis without changing the Gaussian shape.

To store a general deformed covariance back as rotation and scales, diagonalize the symmetric Σ ′ = Q Λ Q T , require positive eigenvalues, and use scales λ j . Choose eigenvector signs so det Q = + 1 before converting to a quaternion. At repeated eigenvalues, orientation is not unique; preserve continuity or retain the full covariance rather than interpreting an arbitrary eigenvector flip as physical rotation. Covariance push-forward changes shape, not a conserved physical mass. If opacity is an appearance peak it may be held fixed by policy; preserving an extinction or density integral needs a separately defined field and Jacobian rule. Do not silently assume either policy from A Σ A T .

A useful edit transaction has a before state, a proposed state, and a commit decision. Store the edit ID, parent scene revision, selected stable IDs, association-table revision, operator and parameters, before/after state hashes, affected Gaussian IDs, and validation results. Write the candidate state to a separate revision. Validate finite means, normalized orientation, positive-definite covariance, valid support weights, and stable ID uniqueness before publication. Render the candidate from the same cameras used for the before state. Compare the intended region and the declared unaffected region separately; include color, depth and dominant-ID checks where available. Commit the new revision only if all declared conditions pass. Otherwise retain the prior revision and the failed report. A provenance record makes a result repeatable; it does not make the physical interpretation true by itself.

A selected rigid cabinet has three associated Gaussians with stable IDs 51, 64 and 92. The cabinet is translated by b = ( 0 , 2 , 0 ) with A = I . Their support weights each sum to one. For Gaussian 64, the old mean is ( 3 , 1 , 0 ) and covariance is

Σ = [ 4 1 0 1 2 0 0 0 0.25 ] .

The renderer’s current vector indices for IDs 51, 64 and 92 are ( 8 , 2 , 11 ) , but a depth sort changes them to ( 5 , 10 , 1 ) . State the new mean, covariance, selected identity after sorting, and the minimum checks before committing.

Solution. Translation gives μ ′ = μ + b = ( 3 , 3 , 0 ) . Since A = I , Σ ′ = I Σ I T = Σ ; translation does not change footprint. The selected identity remains ID 64, whose new transient index is 10. It is incorrect to preserve index 2 as the selection. Limits and exit check

A Gaussian is a learned appearance primitive, not automatically a surface point, rigid body, collider, or mass element. An association table is a model chosen for an application, and ambiguous or incomplete support should remain visible as uncertainty. The affine covariance rule preserves a Gaussian footprint under a locally affine map; it does not solve visibility, self-intersection, cloth topology, contact, or appearance changes caused by newly revealed surfaces. A render that matches the original cameras cannot prove an edit is physically correct from unseen views.

Before calling a captured-world edit complete, a learner should be able to: trace a semantic selection through stable IDs after reordering; show that normalized support weights reproduce a shared affine transform; derive and calculate A Σ A T ; identify a rank-deficient local fit; rotate or preserve SH according to a stated frame; and produce a provenance record plus before/after tests for affected and unaffected regions. The original 3DGS paper establishes a view-synthesis representation and renderer, not these editor, physics, or publication contracts. Those are additional systems that must be designed and verified explicitly.

Train the splats only after the forward renderer is understood

A projected, tiled, ordered, composited image is now a complete forward result, and the preceding CPU/GPU comparison gives us checks for color, depth, dominant ID, tile occupancy, and sorting. We can now ask the inverse question: how should the stored splats change so that this renderer matches calibrated photographs? This is where training belongs in the story: the forward map and its failure signals are already visible. The original 3D Gaussian Splatting paper starts from sparse points from camera calibration when available, optimizes their attributes, and interleaves optimization with density control. A rasterizer tutorial without this lifecycle explains only inference, not how the captured representation is fitted. (Kerbl et al., 2023 paper)

The author implementation used below is pinned to commit 54c035f7834b564019656c3e3fcc3646292f727d, committed 30 October 2024. It is a precise historical source specimen, not a claim about every later fork or current 3DGS implementation. Its train.py uses a weighted L 1 and structural-similarity image loss, optionally adds depth regularization, differentiates the loss, gathers projected-mean gradient statistics, performs scheduled density control and opacity reset, then steps the optimizer. Its GaussianModel maps stored scale through exp , opacity through σ , and normalizes rotation quaternions. A robust importer or optimizer must still reject or explicitly repair a zero quaternion: normalization alone does not turn a zero vector into a valid rotation.

For calibrated camera k , captured image I k , valid pixel set Ω k , and renderer R k ( Θ ) , a simplified scalar-channel objective is

L ( Θ ) = ∑ k ∈ B 1 | Ω k | ∑ p ∈ Ω k ρ ( R k ( Θ ) p − I k , p ) ,

where B is the sampled batch and ρ is the declared penalty. In the pinned training loop, the image term is a weighted L 1 plus DSSIM loss; when reliable depth supervision is enabled, a weighted inverse-depth L 1 term is added. The objective’s exact weights and preprocessing are part of the experiment. Lower image error does not prove unique or physically useful geometry: several scenes can explain the same measurements, and a view-synthesis representation can exploit appearance to hide geometric error.

The reference stores several parameters in unconstrained form: mean μ ∈ R 3 ; log-scale s l o g decoded as s = exp ⁡ ( s l o g ) > 0 ; quaternion q normalized before it constructs a rotation; opacity logit a decoded as o = σ ( a ) ∈ ( 0 , 1 ) for finite real a ; and appearance coefficients such as spherical harmonics. These choices make ordinary optimizer steps compatible with positive scale and bounded opacity. The opacity derivative can still saturate near zero or one.

Derive the image gradient through a Gaussian’s footprint

At pixel x , the Gaussian’s spatial weight is G ( x ) = exp ⁡ ( − q ( x ) / 2 ) , where q is its squared elliptical distance. Before implementation-specific clamping, its effective sample opacity is

α ( x ) = o G ( x ) , o = σ ( a ) .

For a pixel where this unclamped branch is active and the footprint is held fixed,

∂ α ∂ a = G o ( 1 − o ) .

If the renderer clamps o G at a maximum, the derivative is zero on the saturated branch. The factor α ( 1 − α ) is only the special case G = 1 ; in general it is wrong because the Gaussian’s footprint weight is separate from stored opacity.

For two ordered splats in one color channel over background c b , compositing gives

C = α 1 c 1 + ( 1 − α 1 ) [ α 2 c 2 + ( 1 − α 2 ) c b ] .

Holding order, centers, and footprint weights fixed, the color and front-opacity derivatives are

∂ C ∂ c 1 = α 1 , ∂ C ∂ c 2 = ( 1 − α 1 ) α 2 , ∂ C ∂ α 1 = c 1 − [ α 2 c 2 + ( 1 − α 2 ) c b ] .

With squared error ℓ = 1 2 ( C − y ) 2 , the chain rule yields ∂ ℓ / ∂ c 1 = ( C − y ) α 1 and ∂ ℓ / ∂ a 1 = ( C − y ) ( ∂ C / ∂ α 1 ) G 1 o 1 ( 1 − o 1 ) in the unclamped branch. Position and covariance gradients continue through the projected center and conic because changing them changes q ( x ) and thus G ( x ) . Discrete tile membership, depth order, threshold crossings, and split/clone decisions are not ordinary smooth parameters; they form separate algorithmic boundaries.

A hand-checkable toy makes the chain rule concrete. Set both footprint weights to one, so the unclamped α i = o i ; this is an explicit unit-footprint assumption, not the general pixel case. Use α 1 = o 1 = 0.5 , c 1 = 0.8 , α 2 = o 2 = 0.25 , c 2 = 0.2 , c b = 0 , target y = 0.4 . Then C = 0.425 , residual C − y = 0.025 , and

∂ ℓ ∂ c 1 = 0.0125 , ∂ ℓ ∂ α 1 = 0.01875 , ∂ ℓ ∂ a 1 | G 1 = 1 = 0.0046875 .

A direct scalar SGD illustration with η = 0.1 gives c 1 ′ = 0.79875 . If alpha were optimized directly, α 1 ′ = 0.498125 . With the stored logit, a 1 ′ = a 1 − 0.00046875 ; near a 1 = 0 , decoded opacity changes by about one quarter of that logit step because d σ / d a = 0.25 . A production run instead accumulates gradients from many pixels and camera views and uses adaptive optimizer state; this one-pixel trace checks signs and factors only.

Density control changes model size between gradient steps

Continuous optimization cannot add a primitive when current support is inadequate. The pinned implementation accumulates the norm of the first two components of the projected-mean gradient for visible Gaussians and divides by a visibility count to estimate an average image-space signal (add_densification_stats). At scheduled intervals it applies two capacity operations:

  • Clone: when the accumulated mean-gradient magnitude reaches the threshold and the largest world-space scale is no greater than percent_dense * scene_extent, copy that small primitive’s mean, appearance, opacity, scale, and rotation into a new primitive. The original remains. This adds local representation capacity without moving either copy.
  • Split: when the gradient reaches threshold but the largest scale exceeds that cutoff, replace the broad primitive with N children. In this pinned code N = 2 by default. It samples a zero-mean offset whose standard deviation is the parent’s three scales, rotates that offset by the parent’s rotation, and adds it to the mean. Child scales are divided by 0.8 N before mapping back through the inverse scale activation. Then the parent is removed. The samples are random in the parent’s anisotropic local coordinates; the reference does not deterministically split along the single largest axis.

The cited source performs clone first and split second. It then prunes primitives whose opacity is below the scheduled minimum; after the configured size gate it also prunes those whose recorded screen radius is too large or whose maximum world scale exceeds 0.1 times the scene extent. It finally resets scheduled opacities by capping decoded opacity at 0.01 , mapping back to logits, and resetting that parameter group’s Adam moments. Those are choices of this revision, not universal constants or a claim that every fork follows them. (densify_and_prune, split and clone; reset_opacity)

The training-loop ordering matters. At the cited revision, loss.backward() runs first. Inside the no-gradient control block, the program accumulates visible gradient/radius statistics, performs any scheduled clone/split/prune, performs any scheduled opacity reset (also at the first density-control iteration for a white background), and only then calls the exposure and Gaussian optimizer steps and clears gradients. It does not do optimizer-step-then-density-edit as a generic pseudocode might suggest (train.py, lines 142 and 163–186).

The model code must keep variable-length tensors and optimizer state aligned. When it appends children, it appends zero rows to Adam’s exp_avg and exp_avg_sq; when pruning, it slices those moments by the same keep-mask; opacity reset replaces the opacity parameter and zeros that parameter’s two moment tensors (GaussianModel, lines 316–405). This revision constructs new Parameter objects during append/prune/reset and does not transfer the just-backpropagated .grad tensor to those replacements. Consequently, on an edit step those replaced groups have no gradient for the immediately following optimizer call; their stored Adam moments are preserved/sliced or reset as the code specifies, and the next render/backward populates gradients for the new parameters. This behavior follows from the pinned PyTorch code path; it is an implementation fact to verify again when changing frameworks or revisions.

A small branch trace (numbers are teaching values, not source defaults): average projected-mean gradients are [ 0.02 , 0.31 , 0.24 ] , largest world scales are [ 0.08 , 0.70 , 0.04 ] , and the example gradient threshold is 0.20 with a small/large cutoff of 0.10 . The first splat stays; the second splits; the third clones. If the second has opacity 0.003 and the example opacity floor is 0.005 , its children may be created by the clone/split operation and then removed by the later prune mask if they inherit that low opacity. A faithful trace must apply the implementation’s actual sequence, rather than silently moving the opacity prune ahead of growth. For each append, initialize child moments to zero; for parent removal, slice all parameter and per-splat statistic arrays with the same keep-mask. This example teaches the branch and ordering, not expected quality or useful production thresholds.

A complete scalar training-step laboratory

The following complete Python program checks the two-splat color/logit derivatives against 240 finite differences, rejects the tempting wrong footprint chain rule, verifies a small SGD step, and tests stable identity and optimizer-moment alignment during a declared prune/clone policy. Run it with python3 tools/labs/gaussian_training_step_lab.py or with python3 -O tools/labs/gaussian_training_step_lab.py. It models one scalar pixel with fixed footprint and ordering; it does not train geometry, reproduce Graphdeco topology ordering, or validate GPU gradients. Implementation explanations are beside the operations in the code.

#!/usr/bin/env python3
"""A scalar two-splat gradient and topology-state lab, not a scene trainer."""
from dataclasses import dataclass, replace
import math
import random


def require(condition, message):
    # Checks remain active under python -O; these are executable lesson claims.
    if not condition:
        raise AssertionError(message)


def sigmoid(x):
    # Branch to avoid overflowing exp for a large negative or positive logit.
    if x >= 0:
        return 1 / (1 + math.exp(-x))
    e = math.exp(x)
    return e / (1 + e)


def loss_and_gradient(parameters, footprints, target, background=0.0):
    # The trainable vector is (front color, back color, front logit, back logit).
    # Geometry, sorting order and the Gaussian footprint values are held fixed.
    c1, c2, a1, a2 = parameters
    g1, g2 = footprints
    if not all(math.isfinite(v) for v in (*parameters, *footprints, target, background)):
        raise ValueError('All scalar inputs must be finite')
    if not (0 <= g1 <= 1 and 0 <= g2 <= 1):
        raise ValueError('This unclamped teaching model requires footprints in [0,1]')
    o1, o2 = sigmoid(a1), sigmoid(a2)
    alpha1, alpha2 = o1*g1, o2*g2
    behind = alpha2*c2 + (1-alpha2)*background
    color = alpha1*c1 + (1-alpha1)*behind
    residual = color-target
    # Chain rule: pixel alpha = opacity * footprint. Its logit derivative is
    # g*o*(1-o), NOT alpha*(1-alpha), unless the footprint equals one.
    dcolor = (alpha1, (1-alpha1)*alpha2,
              (c1-behind)*g1*o1*(1-o1),
              (1-alpha1)*(c2-background)*g2*o2*(1-o2))
    return .5*residual*residual, tuple(residual*d for d in dcolor), color


def finite_difference(parameters, footprints, target, axis, step=1e-6):
    # Re-evaluate the forward loss twice. This oracle does not use the analytic
    # derivative, so a missing transmittance or footprint factor is detectable.
    if not math.isfinite(step) or step <= 0:
        raise ValueError('Finite-difference step must be finite and positive')
    lo, hi = list(parameters), list(parameters)
    lo[axis] -= step
    hi[axis] += step
    return (loss_and_gradient(hi, footprints, target)[0]
            - loss_and_gradient(lo, footprints, target)[0])/(2*step)


@dataclass(frozen=True)
class ScalarSplat:
    # Only one scalar parameter and its two Adam moments are represented here.
    # Real trainers maintain aligned state for every trainable parameter group.
    identity: int
    parameter: float
    first_moment: float
    second_moment: float


def prune_and_clone(records, prune_ids, clone_ids):
    # This lab chooses prune-before-clone, with pruning winning conflicts.
    # It is a declared teaching policy, not Graphdeco's exact control order.
    identities = [r.identity for r in records]
    if len(identities) != len(set(identities)):
        raise ValueError('Stable identities must be unique')
    if not (set(prune_ids) | set(clone_ids)) <= set(identities):
        raise ValueError('An edit refers to an absent identity')
    output = [r for r in records if r.identity not in prune_ids]
    next_id = max(identities, default=-1) + 1
    for parent in records:
        if parent.identity in clone_ids and parent.identity not in prune_ids:
            # The child copies the parameter, but starts with zero moments.
            # Survivors retain their own moments despite changing array indices.
            output.append(replace(parent, identity=next_id,
                                  first_moment=0.0, second_moment=0.0))
            next_id += 1
    return output


def run():
    parameters = (.8, .2, 0., math.log(1/3))
    loss, gradient, color = loss_and_gradient(parameters, (1., 1.), .4)
    require(math.isclose(color, .425), 'Worked pixel color')
    require(math.isclose(gradient[0], .0125), 'Front color gradient')
    require(math.isclose(gradient[2], .0046875), 'Front logit gradient')
    # A small simultaneous update lowers this particular local loss. It does
    # not establish global convergence or identify a 3-D scene from one pixel.
    updated = tuple(p-.1*g for p, g in zip(parameters, gradient))
    require(loss_and_gradient(updated, (1., 1.), .4)[0] < loss, 'Local SGD descent')

    rng = random.Random(731)
    for _ in range(60):
        p = (rng.uniform(-.2, 1.2), rng.uniform(-.2, 1.2),
             rng.uniform(-3, 3), rng.uniform(-3, 3))
        footprints = (rng.uniform(.05, 1), rng.uniform(.05, 1))
        target = rng.uniform(-.1, 1.1)
        _, analytic, _ = loss_and_gradient(p, footprints, target)
        for axis in range(4):
            numerical = finite_difference(p, footprints, target, axis)
            require(math.isclose(analytic[axis], numerical, rel_tol=2e-5, abs_tol=1e-8),
                    'Finite-difference gradient disagreement')

    # A deliberate wrong formula must disagree when footprint != 1.
    _, correct, c = loss_and_gradient(parameters, (.35, .8), .4)
    alpha = sigmoid(parameters[2])*.35
    behind = sigmoid(parameters[3])*.8*parameters[1]
    wrong = (c-.4)*(parameters[0]-behind)*alpha*(1-alpha)
    require(not math.isclose(correct[2], wrong, rel_tol=1e-3),
            'The negative chain-rule example must expose the missing footprint')
    require(sigmoid(-1000.) == 0. and sigmoid(1000.) == 1., 'Finite saturation')

    original = [ScalarSplat(7, .2, .3, .4), ScalarSplat(9, .8, .7, .6)]
    edited = prune_and_clone(original, {7}, {7, 9})
    require([r.identity for r in edited] == [9, 10], 'Prune wins; child gets new identity')
    require(edited[0] == original[1], 'Survivor state follows identity, not old index')
    require(edited[1].parameter == .8 and edited[1].first_moment == 0
            and edited[1].second_moment == 0, 'Child state initialization')
    require(len(original) == 2, 'Topology edit leaves source checkpoint immutable')
    for bad in ([original[0], original[0]],):
        try:
            prune_and_clone(bad, set(), set())
        except ValueError:
            pass
        else:
            raise AssertionError('Duplicate identity accepted')
    try:
        finite_difference(parameters, (1, 1), .4, 0, step=0)
    except ValueError:
        pass
    else:
        raise AssertionError('Zero finite-difference step accepted')
    print('PASS: worked gradient, SGD, 240 finite differences, wrong-chain rejection, '
          'saturation, topology/moment identity and negative inputs; scalar CPU model only')


if __name__ == '__main__':
    run()
