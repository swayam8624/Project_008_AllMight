## High-priority integration-specific gaps

The book's strongest transferable insight is that every representation has a consumer and deadline. An asset's bytes may exist in an I/O completion buffer without existing as a live GPU resource; an event may be received during a display frame without being consumed by a fixed simulation tick; an animation pose may be computed without being committed as an authoritative collision transform; a world object may have a durable authored identity without having a resident runtime instance; a service may have been constructed without all its dependencies completing startup. Existing topic sections may individually be correct while those **hand-off contracts** are absent.

**Priority 1 — lifecycle:** document successful-service tracking, rollback, teardown and the particular failure that destroys temporary objects but must not destroy providers prematurely. A failed start must clean up its own partial allocation even if the coordinator only stops successfully started services.

**Priority 2 — input:** separate physical device reports, captured UI focus, logical action mapping, fixed-tick edge storage and recorded replay commands. Use radial dead-zone remapping for both axes, note that filters change delay and require a policy, and distinguish vibration/rumble *output* from input.

**Priority 3 — streaming:** distinguish request, read/decompress/validate, publication and retirement. Use request generations so cancellation cannot publish a stale completion. Budget peak transient and GPU-in-flight memory rather than only resident asset bytes; identify which consumer can block unloading and when an unresolved cross-cell reference is legal.

**Priority 4 — animation/world:** separate provisional clip evaluation, gameplay/root-motion request, physics contact resolution, final pose and draw packets. Do not treat a post-physics visual root transform as a second independent motion command. Prevent double-fired side effects when display frames and simulation ticks differ.

**Priority 5 — observability:** layer event logs, per-cell streaming state, resource budgets and end-to-end action/tick identification. Existing profiler and crash facilities should be reused, not recopied.

## New local executable witness and its limit

A standalone **C++20** laboratory was created and compiled in the accompanying conversation as *engine_world_contract_lab.cpp*. It exercises dependency-ordered startup and rollback; radial analog dead zones; retention of a press and release across fixed-step sampling; stale async completion rejection by generation; resident memory budgeting and unresolved object references; and render interpolation that does not modify authoritative state. The revised file passed strict Clang C++20 -O2 -DNDEBUG with AddressSanitizer and UndefinedBehaviorSanitizer, plus GCC C++20 -O2 -DNDEBUG with warnings as errors, in the local authoring environment. It additionally rejects startup cycles before side effects and prevents duplicate root-motion application in the same simulation tick. **The revised laboratory has been committed to the GitHub repository and embedded verbatim in the canonical Game Engine volume on the Gregory integration branch.** It models deterministic completions and object state; it is **not actual asynchronous filesystem I/O, audio output, animation, GPU resource retirement, engine integration or a production service manager**. No remote CI run is claimed.
